# Proposal

## Why

`docs/STATUS.md`（基于 `851419c4`）仍有六条现象，全部是**用户可感知的速度/稳定性**问题：

- shell 启动慢
- 简体中文退格稍慢
- 文本选择性能不足，且拖动一侧时另一侧的匹配区域会变动（该侧指针未动）
- 上下滚动卡顿
- 切换应用返回时闪烁
- 文件提供者响应慢

上一轮变更 `2026-10-17-status-open-items-closure` 明确不覆盖这六条（它的 proposal 末段
已把当时仍开着的现象划给后续变更）。这些现象没有归属、没有可复现的度量，任何一次
「感觉快了」都无法被复核。本变更把每条收敛到「度量 → 根因 → 代码落点 → 同一度量复测」，
并在 `tasks.md` 留下当次数字与提交。

同时补齐维护者要求的三类预览截图仪器测试：安装 bootstrap 后用包管理器安装并运行
`fastfetch` 截图、打开侧边面板截图、打开设置截图。截图不是装饰：它是渲染、输入、
主题、会话抽屉与文件系统的端到端证据。

## What Changes

严格串行，每节一项，先量后改：

1. 六条 STATUS 现象逐条落地（`tasks.md` 一…六节），每条至少给出一个可重复运行的
   仪器测试或单元测试，断言写在**用户可见的量**上（首帧时间、退格到回显、拖动帧耗时、
   滚动帧耗时、返回后首帧、列举耗时），而不是日志里的一句「成功」。
2. 预览截图测试（七节）：`PreviewScreenshotTest` 真实安装 bootstrap、用 `pkg` 装
   `fastfetch` 并运行，再截会话抽屉与设置；截图以 PNG 落盘并断言分辨率、颜色数与
   内容特征，防止「拍了一张黑屏也算通过」。
3. 质量门禁与规范（八节）：`nu scripts/check.nu` 全绿；`openspec/specs` 与实现同步；
   更新 `docs/STATUS.md` 前先在 tasks 里拿到可复核的证据。
4. 收尾（九节）：连续三轮独立审阅，记录每轮发现与处置。

## 非目标

- 不重做渲染器或输入法架构；只修根因与可验证的性能路径。
- 不为截图测试引入 vendor 的 APK/字体/测试数据；bootstrap 取官方发布产物，
  允许经 `-e test.bootstrapUrl file://…` 指向本地同名产物以适配无外网 CI。
