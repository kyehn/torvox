## 应用自身问题与修复

### 1. 普通退出码被误判为 execve 失败

等待线程原先把所有 `code >= 100` 当作 `100 + errno`，导致 shell 的正常退出码被解码成
不存在的 errno。修复为只接受 `1..=133` 的 errno；子进程侧也把 errno 封顶到 133，
使编码后的退出码不超过 233。纯函数 `execve_errno_from_exit_code` 覆盖边界单测。

### 2. 重复拆卸

`request_exit` 改为先 `exited.swap(true, AcqRel)`：

- 第一次调用继续断通道、发信号；
- 第二次调用断通道后直接返回；
- 等待线程已回收子进程时同样短路；
- `getpgid` 返回 `ESRCH` 时不再发信号，避免 PID 复用误伤。

### 3. 收尾日志与启动期时序误分级

子进程与本进程同组、子进程已退出、`getpgid` 取不到组号都是安全退化路径，统一改为 debug：
组杀目标不可用时直杀子进程，信号语义不变，正常收尾不再产生 warn。`TerminalSurface`
在 `surfaceCreated` 之前收到尺寸变化属于正常启动时序，延后重试的日志同样降为 debug。

## 平台与外部条目

- **厂商 GPU 分配器**：交换链实际选择 `Rgba8Unorm`，字形图集也是 RGBA8；分配器仍报告
  不支持的 R8 探测。它发生在交换链配置之前，属于驱动/系统合成路径，应用侧没有开关。
- **外部包 SELinux**：绝大多数是 `granted`；少量 `denied` 是外部 proot 启动期读取
  `/proc` 的硬件探测，不影响终端。应用无权修改自身 SELinux 域。
- **系统 Binder / SurfaceFlinger / 系统属性 / 系统字体 / 框架资源**：调用栈均在平台线程，
  无应用栈；不做无法落地的绕过。
- **上游终端协议**：未实现的 CSI 与 kitty graphics 查询来自外部图片/终端工具；
  解析库把错误写回客户端，文本终端不受影响。

## 慢帧调查

两份日志共 551 条帧/循环观测：第一份 80 条慢帧、26 条慢循环；第二份 385 条慢帧、
60 条慢循环。

第二份日志的慢帧集中在滚动期间：

- 385 条慢帧中 379 条 `scrollOffset>0`，只有 1 条 `newOutput=true`；
- 单帧 53.5–99.8ms，中位 59.2ms；
- 每个滚动事件通常对应两帧：一帧约 2ms，紧接一帧约 59ms；
- 只有 1 条慢帧包含 GPU 分段：`acquire` 占 32.9ms，编码 0.4ms、提交 0.8ms、
  呈现 3.1ms，取帧等待占该帧总时长的 88%；其余慢帧来自尚未带分段日志的构建。

已新增三级观测，并按取帧证据调整排队深度：

- `SLOW_RENDER_INNER`：拆出阶段一、接收、渲染锁等待、GPU 调用与总时长；
- `SLOW_CELL_BUILD`：拆出实例构建与 GPU 调用；
- `SLOW_RENDER_PHASE`：拆出取帧、编码、提交、呈现；
- 交换链排队深度由 3 帧降为 2 帧：`acquire` 是唯一显著分段，三帧排队会把等待
  放大到 2–3 个 vsync；双缓冲保留流水线，同时压低等待上限。

下一步在 Mali 真机复测同样的滚动，确认 `acquire` 占比下降；若仍是取帧等待，
再判断是驱动呈现节拍还是 GPU 回压，不以猜测替代。

## 复现与取证

1. 启动应用，等 shell 提示符出现并静置；
2. 产生至少两屏历史；
3. 连续上滑/下滑 3–5 秒；
4. 抓取包含 `SLOW_FRAME`、`SLOW_LOOP`、`SLOW_RENDER_INNER`、`SLOW_CELL_BUILD` 的日志，
   只保留聚合结果，不把原始日志加入仓库。
