# 两条仪器化用例的时序与口径

对应两处全量套件红灯：`KittyGraphicsPlacementTest.kitty_image_moves_up_with_scrolled_content`
与 `UiAutomatorTest.typingViaSystemKeyboardReacts`。两处都不是产品缺陷，改动只在
`androidTest` 源集内；本留档记根因、取证与判据口径。

证据采集环境：x86_64 模拟器（软件 Vulkan），`:app:connectedDebugAndroidTest` 全量
231 例。只写结论与计量，不写原始日志行、时间戳、PID、设备标识。

## 一、Kitty 图像位移：滚动量写死了

### 症状

全量套件红灯：断言「图像必须随内容上移 51.0px（实际 68px）」。68px 恰是 4 个
单元格高（单元格高 17px），即图像确实随内容上移了，只是上移了 4 行而不是 3 行。

### 根因

滚动命令经 shell 执行：

```text
printf '\033[38;1Hk-scroll\nk-scroll\nk-scroll\n'\n
```

终端宽 30 列，这条命令连回显共 44 字符，回显折成 2 行；命令输出再占 3 行；shell
还会补一行提示符。**视口实际上滚了 4 行**，而用例把期望值写死成 3 行——判据与
被测行为不同口径，量具失效。

### 改法

- 滚动改走 VT 解析器（`Bridge.feedTerminal`）而不是 shell：光标移到末行后连续
  换行 N 次即上滚 N 行，不经命令回显与提示符，滚动量成为常数。
- 位移期望值不再写死：改用**渲染帧的回滚长度**（`renderedScrollbackLength`）作
  口径——它与屏幕像素同源，「这一帧内容往上滚了多少行」与「图像在像素上移了
  多少行」由此同口径；拿 VT 线程的当前值去比像素，两者可能不在同一帧。
- 取样要求连续两帧的「包围盒 + 回滚长度」都相同才算稳定：渲染线程可能还没追上
  最新的回滚长度，此时截到的仍是上一帧。

### 判别力是否保住

保住。缺陷 1（放置缓存漏掉回滚长度 → 图像钉在原处、后续内容从它下面滚过去）
在改法下依然判红：回滚长度不变时缓存不失效，位移为 0，与「随内容上移的行数」
判不相等。

### 实测计量

- `kitty_image_scrolled_rows=3`（滚动量确为 3 行）
- `kitty_image_scroll_shift_px=51`（= 3 × 17px，与滚动量一致）
- `kitty_image_scroll_pixels=4096`（图像未被文本覆盖，像素数不变）
- `kitty_placeholder_pixels=4096`（Unicode 占位符路径不受影响）

## 二、UiAutomator 搜索：抽屉动画期间按旧坐标点击

### 症状

全量套件两次都红在同一处：`AssertionError: Search text field should appear`。
单跑该类三次全绿——典型的「与上下文相关」的偶发红灯。

### 取证

读全量运行里该用例的 logcat，UiAutomator 自己的日志给出了时序：

- 抽屉按钮被点击；
- 408ms 后就查到了 `SearchButton` 节点（抽屉滑入动画未完，节点已进无障碍树）；
- 随后的点击没有产生搜索框。

无障碍树里的节点边界**落后于实际绘制位置**：动画期间节点的边界还在滑入途中的
位置，按它给出的坐标点击会落到抽屉的遮罩上——遮罩把抽屉关掉，搜索框自然从未
出现。真实用户按的是眼睛看到的当前位置（已在按钮上），不会落到遮罩；这是量具
的时序问题，不是应用缺陷。

### 改法

- 点之前等节点**可见边界停稳**（连续两次取样相同），且边界须完整落在屏幕内：
  过期节点或尚未滑入的节点点了必然落空。
- 点完**校验结果**：搜索框没出现就重开抽屉再点一次（最多 3 次）。
- 失败信息附上无障碍树摘要（带 `resource-id` / `content-desc` 的节点及边界），
  下次再红时能直接看出「抽屉开没开」「搜索框在不在」，不必重新取证。

### 判别力是否保住

保住。用例仍断言真实系统键盘的按键经 IME 提交后，应用的搜索结果计数节点出现
且非空——即「输入确实到达了应用」。改动只影响「怎么把抽屉点开」，不影响
「点开后应用有没有反应」这一断言。

## 三、复跑结果

- 全量 `:app:connectedDebugAndroidTest`：231 例 / 0 失败。
- `:app:spotlessCheck`、`:app:detekt` 通过。
- `openspec validate --all --strict` 通过。

## 四、留给下次的判断

- 「Kitty 图像位移」类断言：滚动量必须由用例自己制造（走 VT 解析器），或以渲染
  帧的回滚长度为口径；写死行数只在滚动量确为常数时才成立。
- 「UI 自动化点击」类断言：动画中的界面不能按无障碍树给的坐标直接点；要么等
  边界停稳，要么点后校验并重试。
