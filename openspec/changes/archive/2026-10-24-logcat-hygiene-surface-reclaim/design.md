# Design

## Context

平台收走原生窗口后，应用会走一条自愈链：wgpu 重新配置 surface 失败（校验错误：
`Surface::configure` + 「不支持该适配器的队列族」）→ 渲染帧取不到纹理 → 宿主换新窗口
重挂载 → 恢复。链本身功能正常，但它在日志里的形态是「一次 E + 一次 W」。

日志分级是排障时区分「应用缺陷」与「环境噪声」的第一道闸门。平台事件占据闸门，
等于取消闸门。因此本轮把这条链上的条目按其真实性质重新分级。

同时发现并修掉一个与本规范同源的稳定性缺陷：守卫「execve 失败退出码编码」的用例
在负载高时偶发失败（退出标志先于退出码发布，用例只读一次）。

## Goals / Non-Goals

Goals:

- 平台收走原生窗口导致的渲染失败不产生 warn/error。
- 真异常（自家配置错误、管线缺失、转换失败、attach 失败）仍记 error，判别力不降。
- 分级判据可被自动化测试覆盖，且不随上游文案微调而误判。
- 退出码上报用例与生产路径同口径，不再偶发失败。

Non-Goals:

- 不改动渲染自愈机制本身（换窗口重挂载的时机与次数）。
- 不改变宿主侧瞬时错误的限频次数与节奏。
- 不为「平台收回窗口」引入新的重试或退避策略。
- 不改 `docs/specification/` 与 `docs/STATUS.md`（受保护文件）。

## Decisions

### 1. Rust 侧判据用「错误类型」，不用文案

新增 `GpuError::SurfaceUnavailable(String)` 变体承载「本帧没有可呈现的纹理」，
`is_recoverable()` 只对该变体为真。文案会随实现演进，类型不会；按类型判别可让
分类单测稳定。

「渲染暂停」「surface 尚未挂载」「取帧失败」三条路径同属一类：宿主换新窗口重挂载
或恢复渲染后即恢复，无需人工介入。

### 2. 未捕获 GPU 错误用「校验错误 + 两个上游固定文案」判别

wgpu 只提供 `Error::Validation { description, .. }` 作为可判别字段（`Internal` 等
变体不描述配置失败），故只能读 `description`。判据取两个上游固定文案同时出现：

- `Surface::configure`——来自上游 `handle_error_nolabel(..., "Surface::configure")`
  的调用点标识，保证错误出在配置 surface 上；
- 「不支持该适配器的队列族」——对应 `ConfigureSurfaceError::UnsupportedQueueFamily`，
  保证失败原因是「这个 surface 已经不能用了」，而不是格式不支持、尺寸非法等
  自家配置错误。

两者缺一即判为应用缺陷，仍记 error。措辞若随上游变化，判据只会失效成「一律 error」
——更吵，不会漏报。

### 3. 分级只降不升

可恢复一类降为 debug，其余一律保持 error。宁可多一条噪声，也不可把真缺陷降级：
漏报的代价高于噪声的代价。

### 4. 原生侧给细节，宿主侧给频率

原生侧每次失败记 debug（可恢复时），提供逐次细节；宿主侧按会话汇总
「瞬时渲染错误」，首次记 info、连续出现才记 warn，限频节奏不变。
两侧分工明确：原生侧不刷屏，宿主侧不丢信号。

### 5. 退出码上报用例改为轮询到「可上报」

退出标志有两条置位路径：读线程（PTY EOF）与等待线程（拿到退出码），二者无序。
生产路径本就是逐帧轮询直到可上报（`take_reported_exit` 在码未到手时返回 `None`），
用例却只读一次，负载高时读到中间的 `None` 便失败。改为轮询（有截止时间）后，
用例与生产同口径，且判别力不变：仍然要求「码恰好上报一次」。

## Risks / Trade-offs

- 上游文案变更会使命中判据失效：表现是重新出现一条 E 级噪声，不影响功能与其它
  判据；修复成本是更新两个常量。
- 「渲染暂停」由 error 降为 debug 后，若出现「暂停却继续渲染」的缺陷，信号减弱：
  由宿主侧 info 汇总与暂停/恢复状态日志兜底，且该路径本就不产生帧。
- 新增错误变体改变了 `GpuError` 的形状：全仓无按 `GpuError::Surface` 分支的控制流，
  改动只影响日志分级，无行为差异。

## Migration Plan

- 纯日志分级与测试口径调整，无数据迁移、无配置开关。
- 规范增量落 `specs/logcat-hygiene/spec.md`，归档时同步进主 spec。
- 回归判据：Rust 分类单测（可恢复/不可恢复、上游文案命中与不命中、非校验错误不命中）、
  Kotlin 分级单测（首次非 warn、连续仍 warn）、Rust 全量与 Kotlin 全量单测。
