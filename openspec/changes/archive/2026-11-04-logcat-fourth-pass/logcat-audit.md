# W/E/F 审计汇总（第四轮）

## 数据来源与保留原则

- 审计对象是用户提供的六份设备 logcat；原始文件只在分析期间使用，**不入库、不保留
  副本**。
- 仓内只写聚合计数、标签类别、归因与结论；不写原始日志行、时间戳、PID、设备标识、
  下载链接或可还原设备的细节。
- 计数口径：按 logcat 的 W/E 级标签逐行归并；同一条诊断的多行转储按「行数」与
  「事件数」两栏分别记，避免把转储行当成多条告警。

## 图像介质的两类拒绝

上游对 Kitty 图像协议的传输介质有两处硬性拒绝，判据都在上游源码里：

- **文件与临时文件介质**：上游按**终端进程自己的工作目录**打开客户端给出的路径
  （`readFile` 以 `std.Io.Dir.cwd()` 打开）。客户端给出的路径来自它自己的命令行上下文
  （如相对路径 `test.png`），两个目录不同时必然打不开，上游打 `failed to open image
  file` 并回 `EINVAL: invalid data`。应用侧没有为客户端改写路径的接口，也不能伪造文件
  存在。
- **共享内存介质**：上游在不支持 POSIX 共享内存的平台（含 Android）直接回
  `error.UnsupportedMedium`（`EINVAL: unsupported medium`），客户端随后自行退到可用
  介质。

两处都是上游对「客户端请求的介质在本平台/本进程不可用」的如实应答，客户端按协议
退回可用介质后图像照常显示。

## 上游未实现的协议动作

上游 VT 解析对「终结字节为 `x` 的 CSI」没有分支，落入上游分发器的兜底分支并打出
`unimplemented CSI action`。按上游的格式化语义解码，该序列为 `ESC [` + 中间字节 `*`
与空格 + 无参数 + 终结字节 `x`（上游把空参数切片格式化成 `{  }`，故日志行里参数位
不是空串而是 `{  }`）。它出现在每次 `kitten icat` 发起图像传输之前，与图像传输同线程
同一时刻。

VT 解析全在上游，应用不解析 CSI，也不为协议未定义的动作伪造应答。

## 应用自身旧行为的复核

命令通道丢弃刷屏的根因与修法：

- 旧行为：PTY 输出块在通道满时被直接丢弃，终端状态与 PTY 流逐字节分叉，且每丢一块
  刷一行告警。
- 现行为：PTY → VT 链路是背压点，通道满时把成形后的载荷原样交还调用方重试，调用方
  停止继续从 PTY 通道取数据，通道的容量逐级向上游传递压力，子进程最终因 PTY 缓冲写满
  而阻塞。字节绝不丢弃；残留的入队失败告警按窗口限频并带上窗口内累计次数。

判据：会话层的输出收割用例（背压重试与不丢字节）与命令通道满时的计数用例。
