# 设计

## 职责边界

单元宽度与字形绘制宽度是两件事：

| 事实 | 来源 | 载体 |
| --- | --- | --- |
| 一个单元占几列（1 或 2） | 上游 VT 的宽度表（UAX #11） | `CellData.width` |
| 字形画出来多宽 | 字体的墨迹度量，按位图 1:1 取样 | `GlyphInfo.width` |

渲染层用前者摆格、用后者取样。两者唯一的联系是「宽字符占两格，故其字形四边形
横跨两格」，而不是数值上的倍数关系。

## 用例落位

- 字体层（`render/font/tests/fallback.rs`）：码位不由主字体解析时，由回退面解析到
  真实字形。汉字与符号走同一条链，故共用 `assert_resolved_via_fallback_face` 助手，
  断言口径一致：位图非空、解析面不是主字体、字形号非零。
- 终端层（`terminal/ghostty_terminal/tests/grid_text.rs`）：上游给出的宽度被本仓
  原样传递：宽字符占两列，其后单元的列号跳过这两列。

## 为什么不保留「位图宽度比值」判据

该比值同时踩三条线：

1. **无判别力**：位图宽度比值不参与任何渲染决策，断言它无法区分正确与错误的实现。
2. **不稳定**：比值随宿主字体集而变，同一份代码在开发 shell 与 CI 机器上结论可能相反。
3. **与既有要求抵触**：CJK 字形按位图 1:1 取样，位图宽度即绘制宽度；把它当单元宽度
   判据，等于要求绘制宽度必须随单元宽度线性变化，而该比例由字体决定，不由本仓决定。
