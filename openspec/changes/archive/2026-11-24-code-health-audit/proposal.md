# Proposal

## Why

`code-health` 能力把「重复率、静态形状扫描、依赖活跃度的实测数字与逐处判定必须留档」写成了
硬要求，但规约里这条要求的落点在删除模糊分类目录时一并失效：`openspec/specs/` 下已无承载
这些数字的规范文件，`code-health` 的「审计留档的落点必须可解析」只剩半句「当前落点为……的
『实测基线』小节」，既无文件也无小节。

落点缺失导致三类后果：`code-health` 无法判断重复率与依赖活跃度是否达标；研究台账里指向
「禁改区待维护者裁定项台账」的引用指向不存在的条目；本轮审查的实测数字无处安放，只能靠
口头结论代替可复算记录。

## What Changes

- 新增审计留档 `audit.md`：以已提交树快照为测量对象，重测重复率、代码规模口径、静态形状
  扫描、依赖活跃度四类数字，逐处写明保留重复的理由与每处扫描命中的判定，并给出复现方法
  与 SLOC 统计脚本全文。
- `code-health` 的「审计留档的落点必须可解析」与「静态形状扫描审计结论」写实落点，指向本
  变更的留档；「规范声明的静态检查工具必须与验证门禁一致」补上禁改区台账的落点。
- 恢复「禁改区待维护者裁定项台账（只登记，不实施）」这条要求：规范要求而现行门禁缺席的
  六项只登记事实基线与验收判据，未经维护者明确同意不实施。
- 记录 Timber 的口径冲突：`docs/specification/DESIGN.md` 明文要求使用 Timber，而 Timber
  5.0.1 自 2021-08-13 起无新发布，规范属受保护文件，故登记待维护者裁定而非擅自移除。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `code-health`：审计留档落点写实，禁改区台账归位。

## Impact

- `openspec/changes/2026-11-24-code-health-audit/`：提案、任务、审计留档与规约增量。
- `openspec/specs/code-health/spec.md`：归档时同步上述三条要求并补回台账要求。
- 源码、`docs/specification/`、受保护文件：均不修改。
