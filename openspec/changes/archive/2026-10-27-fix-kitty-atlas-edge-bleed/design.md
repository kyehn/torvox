# Design

## Context

图集布局（`native/src/render/kitty.rs`）把各源子矩形并排写进一张 RGBA 图集，条目
的纹素矩形经 `atlas_offset`/`atlas_region`（按图集尺寸归一化）交给 GPU；KGP 采样器
是 `FilterMode::Linear` + `ClampToEdge`（`native/src/render/pipeline.rs`）。

双线性过滤在纹素边界之外取邻纹素。图集里相邻条目是**别的图像**，条目之间未覆盖的
区域是透明像素，于是边界取样即串色或虚边（见 proposal.md）。

## Goals / Non-Goals

- Goal：越界取样只取本条目自己的边缘像素，四条边一致。
- Non-goal：不改缩放语义——源矩形仍铺满显示区域，不因钳制而裁掉半个纹素。
- Non-goal：不改图集之外的渲染流程（叠加层混合、脏带裁剪、累加器语义均不变）。

## Decisions

### 决策一：采样坐标按条目钳制，而不是给每个条目复制一圈边缘像素

钳制到条目自己的首末纹素中心（`起点 + 0.5` 与 `起点 + 尺寸 - 0.5`）即
「按条目 clamp-to-edge」：边缘片元取本条目的边缘纹素，与在图集里复制一圈边缘像素
得到的结果相同。

- 选它的理由：图集里条带布局的高度不齐（条目可高可矮），按四边 padding 需要为每
  个条目补齐上、下、左、右的复制区，规则与显存开销都随条目数增长；钳制只多两次
  `clamp`，不占显存，条目间也不必留任何空隙。
- 备选「图集 padding」：每条目多占 2 列加若干行，且条目高度不同则底边 padding 行
  各不相同，布局代码显著变复杂。
- 备选「采样器改 Nearest」：缩小的图像出现锯齿，等于用一类缺陷换另一类。
- 备选「着色器内手工双线性（4 次取样）」：多 3 次纹理取样，钳制已达同样效果。

### 决策二：钳制边界由 uniform 的图集尺寸换算

`uniforms.atlas_size` 在 KGP 管线里就是当前图集的纹素尺寸（`ensure_kgp_pipeline`
每帧按 `kgp_atlas_width/height` 重写），条目起点与尺寸乘回去即得纹素矩形，故顶点
阶段把该矩形传给片元阶段即可，片元阶段无需知道布局细节。

### 决策三：图集去掉沟槽列

钳制之后沟槽像素永远采不到：条目边界外的一切取样都被钳回条目自身。留着沟槽只会
让图集变宽、让 UV 口径多出一处分叉，故一并去掉——条目紧挨着排。

## Risks / Trade-offs

- [uniform 里的图集尺寸与纹理不同步 → 钳制边界错位] → uniform 与纹理同源于
  `kgp_atlas_width/height`，且每帧绘制前在 `ensure_kgp_pipeline` 里重写。
- [归一化坐标换算回纹素有浮点误差 → 边界偏差] → 误差量级为 1e-4 纹素，对应的
  邻居权重同量级，既不可见也过不了「纯色像素」断言。
- [去掉沟槽后图集变窄，旧图集与新布局不匹配] → 图集与布局由同一处
  `layout_strip` 产出，图集只在打包时重建，不存在跨版本混用。

## Migration Plan

无数据迁移。改动集中在着色器与图集布局两处，回滚须同时回滚（布局与 UV 口径同处
改动，不会出现半新半旧的图集）。
