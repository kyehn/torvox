# session-liveness Specification

## ADDED Requirements

### Requirement: 新会话首帧必须真正产出并可定位

新建或切到某会话后，该会话 MUST 在合理时间内向 Surface 呈现至少一帧；呈现这一事实
MUST 按**会话**记账，MUST NOT 只用进程级标志——进程级标志在首个会话出帧后恒为真，
后建会话是否出过帧无从判断，「新建会话一片空白」因此既不可观测也不可恢复。

首帧未产出时，MUST 按「挂起必须可定位到层级」与「恢复动作必须按层级分级」处置：
先由其余层级（渲染层、VT 层、输出投递受阻层、生命周期层）解释，**均不成立**时
才归因首帧层。首帧层的恢复动作 MUST 是非破坏性的——向 VT 索要一帧，MUST NOT 关闭
会话：此时没有任何在途工作可归因，尚不能断定会话已死。

首帧计时 MUST 自该会话开始渲染起算，MUST NOT 因渲染线程重启或切后台暂停而重置：
这两者都不改变「这个会话出过帧没有」这一事实。

#### Scenario: 后建会话的出帧事实独立记账

- **WHEN** 首个会话已呈现过帧，随后新建另一个会话
- **THEN** 新会话的「已呈现过帧」事实 MUST 独立于首个会话，且 MUST 在它自己
      呈现第一帧时才成立

#### Scenario: 同步首帧计入已呈现

- **WHEN** 切会话的同步首帧渲染真的呈现了一帧
- **THEN** 该会话 MUST 记为已呈现过帧，开孔的缓冲区覆盖 MUST 随之撤下

#### Scenario: 首帧未产出时归因首帧层

- **WHEN** 会话开始渲染后超过首帧期限仍未呈现任何一帧，且渲染层、VT 层、输出
      投递受阻层与生命周期层皆不成立
- **THEN** 挂起层级 MUST 为首帧层，恢复动作 MUST 为向 VT 索要一帧，
      MUST NOT 关闭会话

#### Scenario: 首帧层不得越过更具体的层级

- **WHEN** 首帧未产出，且渲染帧在途超时（或 VT 线程在途超时、输出投递受阻、
      渲染线程已死）
- **THEN** MUST 归因那个更具体的层级，MUST NOT 归因首帧层

#### Scenario: 渲染线程重启不重置首帧计时

- **WHEN** 会话尚未呈现过任何一帧而渲染线程发生重启
- **THEN** 首帧计时 MUST 沿用原起点，MUST NOT 因重启而重新起算

## MODIFIED Requirements

### Requirement: 挂起必须可定位到层级

看门狗 MUST 判定挂起发生在哪一层，MUST NOT 只给出一个「挂了」的布尔结论。

层级至少 MUST 覆盖：渲染帧在途、VT 线程在途、PTY 输出投递受阻、Kotlin 生命周期
（渲染线程已死而会话仍在运行）、会话自建立起从未呈现过任何一帧。层级判定 MUST 是
纯函数：输入是判定瞬间的快照，MUST NOT 读时钟或全局状态。

判定 MUST 命中即止，且渲染层优先于其余层——渲染帧在途时其余层的读数多半是它的
下游后果。首帧层 MUST 排在最后：它表示「没有任何在途工作，只是内容一直没送到」，
只有其余层皆不成立时才是真正的解释。

#### Scenario: 渲染帧在途被判定为渲染层

- **WHEN** 渲染帧起始时刻早于完成时刻且已超过渲染阈值
- **THEN** 挂起层级 MUST 为渲染层

#### Scenario: 渲染层优先于下游层级

- **WHEN** 渲染层、VT 层与输出投递层的读数同时越过各自阈值
- **THEN** 挂起层级 MUST 为渲染层

#### Scenario: 渲染线程已死判为生命周期层

- **WHEN** 会话仍处于运行态而渲染线程已不存在
- **THEN** 挂起层级 MUST 为 Kotlin 生命周期层

#### Scenario: 始终未出帧判为首帧层

- **WHEN** 会话已越过首帧期限仍未呈现任何一帧，且其余层级皆不成立
- **THEN** 挂起层级 MUST 为首帧层，且 MUST 给出已等待时长

### Requirement: 恢复动作必须按层级分级

挂起后的恢复动作 MUST 由层级决定，MUST NOT 对所有层级一律重启渲染线程。

- 渲染层：MUST 重启渲染线程（渲染线程无状态，重建代价最低）。
- VT 层与输出投递受阻层：MUST 关闭会话，MUST NOT 静默重建——静默重建会丢掉用户的
  shell 状态（工作目录、后台任务、已输入内容），比停在原地更糟。
- 生命周期层：MUST 只记录，MUST NOT 自动处理——Activity 重建、切后台期间不得误杀
  用户的 shell。
- 首帧层：MUST 向 VT 索要一帧（内容去重随之失效，终端毫无变化也会推出该帧），
  MUST NOT 关闭会话——此时没有任何在途工作可归因，尚不能断定会话已死。

#### Scenario: VT 层挂起关闭会话

- **WHEN** 挂起层级为 VT 层
- **THEN** 该会话 MUST 被关闭，MUST NOT 被静默重建

#### Scenario: 输出投递受阻按 VT 层处置

- **WHEN** 挂起层级为输出投递受阻层
- **THEN** 恢复动作 MUST 与 VT 层相同（关闭会话）

#### Scenario: 生命周期层只记录

- **WHEN** 挂起层级为 Kotlin 生命周期层
- **THEN** MUST 只记录诊断，MUST NOT 关闭会话

#### Scenario: 首帧层索要一帧而不关闭会话

- **WHEN** 挂起层级为首帧层
- **THEN** MUST 向该会话的 VT 请求重推一帧，MUST NOT 关闭会话
