# Design

## 问题定位

`fonts.xml` 的声明单位是「面」，而字体库的单位是「文件」：一个 TTC 装一次即含其
全部面，故 `lang` 块里按 weight 重复声明的九个条目指向同一份文件，只需装一次。

两处装库路径原本口径不同：

- 建库路径 `load_font_database` → `load_files`：逐条装入，不去重；
- 补装路径 `missing_region_fallback_faces` → `load_region_fallback_faces`：按文件名
  去重，只补首个。

补装路径的注释已经写明「装一个文件即含其全部面」，建库路径缺同一条约束。

## 方案选择

**在 `load_files` 内按路径去重**，而不是在解析层去重：

- `load_files` 是「字体文件进入字体库」的唯一出口，去重放在这里即成为该不变量的
  唯一守卫，新增调用点不会漏掉；
- 去重键取**解析后的路径**而非声明里的文件名：同一文件可能被不同族以不同文件名
  声明（如用户投放字体与系统字体同名），按文件名去重会漏；
- 按路径去重不需要 `canonicalize`（目标文件可能不存在，规范化还会多一次系统调用）。

**建库时把三族文件合成一份清单**：去重只在单次调用内生效，若主字体、符号族与区域
族分三次装入，跨族的同一文件仍会重复装入。合成一份清单后去重自然覆盖跨族重复，
装入顺序仍是「主字体 → 符号族 → 区域族」，与原来一致。

## 面 id 的影响

`fontdb::ID` 是库内序号，少装一份重复文件会改变后续面的 id。渲染侧的主字面 id 在
建库后一次性取出（`find_monospace_font`），而用户选文件装入的面在**之后**才追加
（库只增不删），故追加位置之后的 id 变化不影响任何已持有的 id。

区域族的补装发生在建库之后，`missing_region_fallback_faces` 的去重本就使补装不再
重复装入；建库去重后，补装路径看到的「已在库内」判定（按文件名）同样成立，两条
路径不会互相打架。

## 验证方式

宿主单测：以真实字体文件为探针，同一路径重复两次交给 `load_files`，断言实际装入
计数为 1，且字体库面数与「只装一次」的参照库相同（无重复面）。
