# 设计

## 现状与根因

规范对逐帧诊断的要求有两层：按窗口输出（每窗口至多一行），以及行内带上窗口内的
事件计数。现有实现只满足前一半。

原生侧的四条慢帧诊断用的是 `SlowLogThrottle::should_log()`：放行时输出一次，
窗口内的命中直接丢弃，行内也没有次数字段。宿主侧的 `SLOW_FRAME` 与 `SLOW_LOOP`
更早，是手写的 `lastSlow*LogNanos` 时间戳比较，形状与原生侧一致。

两份实现都留下同一个缺口：窗口内命中了几次不可见。诊断的价值恰恰在形状——
「持续慢」与「偶发慢」的处置完全不同，而两者在只报单帧耗时的行里长得一样。

## 方案

原生侧改用既有的 `slow_log::CountedLogThrottle`：它已用于命令入队失败、剪贴板
队列溢出、VT 应答队列溢出与呈现帧数统计，语义是「记一次事件；闸门放行时交出
窗口内累计的事件数，窗口内则继续攒着」。把慢帧诊断的闸门换成它，命中次数直接
随该次输出交出，无需另造统计口径。

宿主侧没有可复用的实现，故新增 `CountedLogThrottle`（Kotlin）：与原生侧同语义
（单调时钟判间隔、窗口内计数延后交出而非丢弃），供 `SLOW_FRAME` 与 `SLOW_LOOP`
各持一把。两类诊断仍各自限频，互不吞掉。

字段命名：原生侧行内原有的 `count` 是本次渲染的实例数，与窗口次数不同源，故新
字段取名 `slow_frames`；宿主侧 `SLOW_LOOP` 取名 `slow_loops`。规范要求同一行的
各字段以自身名称标识，两类名字不得互相冒充。

## 取舍

- 不改诊断的触发阈值与分级：本次只补「窗口内次数」这一维度，慢帧仍是 warn，
  阈值仍是 30ms。
- 不动呈现帧数统计（`render_frame: presented N frames`）：它本就带计数，且是
  debug 级。
- 宿主侧闸门非线程安全：每个实例只由一条渲染线程使用，与同包的 `FrameTimingStats`
  同约束；渲染线程是唯一调用方，无跨线程共享。

## 验证

- 宿主侧单测：首条必可见；窗口内被压住；窗口内计数攒着下次交出；时钟回跳不放行。
- 原生侧：`cargo test --lib`、`cargo clippy --all-targets -- -D warnings`、
  `cargo fmt --check`。
- 宿主侧：`:app:testDebugUnitTest`、`detekt`、`spotlessCheck`。
