# 代码健康度审计：重复率与依赖

本留档回答三件事：**哪里在重复**、**重复到什么程度算问题**、**依赖与 vendor 处于什么
状态**。所有数字都可复算：命令、参数、工具版本与采样范围都写在下面。

## 一、重复率扫描

### 方法

- 工具：`jscpd` 4.0.5（nix develop 内的 node 24 环境，`npx --yes jscpd@4.0.5`）。
- 参数：`--min-lines 12 --min-tokens 60`（片段少于 12 行或 60 token 不计）。
- 范围：`native/src` + `native/benches`；`android`（排除 `**/build/**`、`**/*.md`、
  `**/*.toml`、`**/*.lock`、`**/resources/**`）。构建产物与锁文件不参与。
- 语义：同一语言、同一 token 序列、连续行且长度达标即计为 clone。

### 结果与处置

| 范围 | 扫描前 | 扫描后 | 处置 |
| --- | --- | --- | --- |
| Rust | 4 处 / 72 行 / 0.18% | 1 处 / 13 行 / 0.03% | 收敛 3 处 |
| Kotlin | 9 处 / 145 行 / 0.36% | 6 处 / 102 行 / 0.25% | 收敛 3 处 |
| 图标 XML | 1 处 / 12 行 / 1.8% | 1 处 / 12 行 / 1.8% | 保留 |

### 已收敛的真重复

1. **shell 探针会话夹具**（Kotlin，三处 → 一处）
   `CjkPresentSemanticsTest`、`RenderPauseSemanticsTest`、`CjkBackspaceSemanticsTest`
   各自抄了一份「建会话 → 切活跃 → 等提示符 → 销毁」。收进
   `UxTestUtils.withShellProbeSession`：提示符就绪判据与超时只有一份，且会话在
   body 返回（含抛异常）后必定销毁——探针会话是设备上的真实 PTY，泄漏会让后续用例
   看到别人的输出。
2. **输入法可见性与收起**（Kotlin，两处 → 一处）
   `ImePopupPixelInstrumentedTest` 与 `ModifierBarBottomInsetInstrumentedTest` 各写
   了一份 `isImeVisible` 与「收起并确认隐藏」。收进 `TestUtils.isImeVisible` /
   `hideImeAndConfirm`：输入法可见性是**窗口级**状态，两处口径一旦分叉，
   「before 截图必须无键盘」的前提就自相矛盾，像素比对随之失去意义。
   `hideImeAndAwaitHidden` 改为复用同一实现。
3. **基准的配置构造**（Rust，一处 → 一处共用）
   `native/benches/cell_builder.rs` 的下限断言与 criterion 采样各写了一份
   `CellInstanceConfig`；两处字段增减不同步时，断言量到的路径与基准量到的路径便不
   再相同。改为构造一次、两处共用。
4. **会话回归钉的持锁夹具**（Rust，两处 → 一处）
   `session/tests/clipboard.rs` 与 `session/tests/write_backpressure.rs` 各自抄了
   一份「用户写入持住主端写入锁」的线程夹具。收进 `session/tests/mod.rs` 的
   `hold_pty_write_lock`：放行绑在守卫析构上，忘记放行不再拖死进程。
   同一文件里前景/背景「精确 u8」断言的换算也合并为 `exact_rgba`。

### 判定保留的重复

1. **import 块**（Kotlin，5 处）。import 列表天然相似，合并只能靠把导入藏进
   某个文件（如 `*` 通配导入或门面对象），换来的是可读性与静态检查的退化。
2. **图标 XML**（1 处）。`launcher_monochrome.xml` 与 `logo_art.xml` 共用
   `<vector>` 头与 `<group>` 变换；两枚图标是不同资源，抽出公共 `<group>` 会引入
   资源间接层，收益不抵复杂度。
3. **两个 Kitty 放置回归钉**（Rust，1 处 / 13 行）。`selection_search.rs` 里
   「ED2 撤下放置」的断言序列结构相似，但两条钉的是**不同不变式**（直接放置通道 vs
   提示符行 scrollClear 路径），各自的断言消息即是文档；抽成公共函数会让「这条用例
   到底钉住了什么」不再一目了然。

## 二、外部依赖调研

### 判定口径

- **不得引入下载量过少或长期未更新的库**：以 crates.io 的 `downloads`（累计）、
  `recent_downloads`（近 90 天）与 `updated_at`（最近一次发布）为准。
- 本轮采信的门槛：累计下载量 ≥ 100 万且最近 90 天下载量 ≥ 10 万，且最近发布在
  12 个月内。低于任一项即视为「使用面过窄或维护停滞」，不引入。
- 已有依赖按同一口径复核；不达标者给出替换或退出方案。

### 自实现部分是否该换成依赖

逐项核对后**没有发现**值得替换的自实现通用设施：

- **终端协议解析、字形簇切分、单元格宽度**：全部由上游 `libghostty-vt` 提供
  （`cell.graphemes()` 等），本仓不重复实现。
- **PNG 解码**：由上游的 `RustPngDecoder`（`libghostty-vt` 的 `png` feature）在进程
  内完成，本仓只注册解码器（`ghostty_terminal::install_png_decoder`），不另写解码。
- **字体集合与光栅化**：`fontdb` + `swash` + `cosmic-text`。
- **LRU/哈希/并发**：`lru`、`foldhash`、`flume`、`parking_lot`。
- **序列化**：`serde`、`serde_json`、`toml`、`roxmltree`。
- 仓内自行实现的只有**领域逻辑**（渲染管线、字体回退链、终端会话、Kitty 放置、
  SAF 文档提供器），这些不是通用设施，交给第三方只会把控制权交出去。

### vendor 核对

- 仓内**没有** `vendor/`、`third_party/` 目录，**没有** `.gitmodules` 子模块，
  **没有**上游 Zig 源码副本（`find` 全仓无 `*.zig`）。
- 上游 Ghostty 的 Zig 源码由 `libghostty-vt-sys` 的构建脚本在编译期拉到
  `native/target/` 下，**不进入版本库**。
- `du` 结果：`android` 21M、`openspec` 6.4M、`native` 2.3M（不含 `target/`）、
  `docs` 204K。仓库体积由自研代码与文档构成，没有第三方源码堆积。

结论：「降低 vendor」在本仓已无空间——可降的部分早已不在仓里。

### 硬编码核对

仓内的硬编码集中在**协议常量与设备口径**上，而非可配置项：终端网格尺寸、图集尺寸、
PTY 排空期限、轮询间隔、超时上限等。它们各自都有规范或上游依据（见
`openspec/specs/`），并非「该走配置而没走」的残留。唯一在用户侧可配的是
`termux.properties`（`openspec/specs/termux-configuration` 已覆盖）。

## 三、结论

- 重复率：Rust 0.18% → 0.03%，Kotlin 0.36% → 0.25%；余下均为 import 块、图标 XML
  与两个刻意并置的回归钉，逐条判定保留并记录理由。
- 依赖：27 个直接依赖全部通过「累计下载 ≥ 100 万、近 90 天 ≥ 10 万、12 个月内
  有发布」的门槛；没有发现该换成依赖的自实现。
- vendor：仓内零第三方源码副本、零子模块；构建期拉取的上游源码不入库。
