# Proposal

## Why

用户报障：`kitten icat test.png` 显示图像后输入 `clear`，图像不但没有消失，反而跑到
屏幕左上角并变大。

根因是清屏与 kitty 放置撤下的时序：

- 提示符行上的 ED2 走「旧行连同放置滚进回滚区再清屏」的路径。放置已不在屏幕上，
  清屏自然撤不下它们。
- 紧接着的 ED3 清回滚区时，上游把被删行里放置的锚点搬回屏幕左上角，且不标记其
  失效。放置于是复活在左上角。

上游的「清屏撤下放置」只在活动区清屏路径上生效；走回滚路径时撤不下已被滚走的
放置，锚点又会被搬回屏幕。终端侧必须在清屏序列之前显式撤下放置，才能保证
「一次清屏即清干净」。

## What Changes

- 输入过滤层识别 ED2（`CSI 2 J` / `CSI 22 J`）与 ED3（`CSI 3 J`），按上游
  `parse_table.zig` 的字节划分解析 CSI 参数与中间字节，记录清屏序列在载荷中的位置。
- 清屏序列之前插入 kitty 删除命令：ED2 撤下全部可见放置（`a=d,d=A,q=2`），ED3 按
  图像 id 撤下锚在回滚区的放置（`a=d,d=I,i=<id>,q=2`）。
- 删除命令 MUST 静默（`q=2`）：删除成功本就不回包，失败也不回，终端不会因此多出
  应答或日志。
- 不改公开 API：清屏检测与删除命令插入都发生在既有写路径内部。

## Capabilities

### Modified Capabilities

- `kitty-graphics`：扩写「清屏必须立即撤下图像放置并清除像素」要求，覆盖回滚路径
  与清回滚区的时序。
