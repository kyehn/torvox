# Design

## Context

审计应用进程内的日志条目时，E 级只剩两类：渲染线程被中断时的取消异常、原生侧窗口判死。
W 级里除逐帧慢诊断（已按 500ms 窗口限频，符合规约）外，还有原生窗口重挂载、宿主换新
窗口的请求、视图未附着时跳过选择菜单，以及平台因应用连续弹提示而打出的窗口冲突告警。

逐帧慢诊断经复算已合规：同一会话内两次输出间隔不小于 500ms，窗口内次数随行给出，
因此不改其实现，只在审计结论里纠正口径。

## Goals / Non-Goals

**Goals:**

- 让应用自身的正常路径不再产生 warn 或 error，让 W/E 闸门只留给真正的缺陷。
- 消除应用自身触发的框架告警（提示窗口冲突）。

**Non-Goals:**

- 不改逐帧慢诊断的限频实现：复算表明其已满足 500ms 窗口要求。
- 不引入日志框架或集中式日志器：分级判据仍就地放在作出判定的位置。

## Decisions

- 中断的判据取异常的 cause 而非类型：取消异常也可能来自协程作用域被取消，只有 cause 是
  `InterruptedException` 时才说明是线程被中断。判据抽成纯函数以便单元测试覆盖。
- 原生窗口判死记 debug、重挂载记 info：平台收走窗口后取纹理必然失败，宿主换新窗口即恢复；
  新窗口迟迟不来的异常由宿主侧的重建预算裁决并升级为 error，原生侧不先一步报同一件事。
- 宿主换新窗口的请求首次记 info、连续记 warn：首次是自愈路径的第一步，连续才说明新窗口
  迟迟不来。判定同样抽成纯函数。
- 提示改由单例投递器发出：取消与展示都经主线程消息队列，取消在前、展示在后，平台先摘
  旧窗口再挂新窗口。投递器用应用上下文建提示，避免静态引用把 Activity 钉住。
- 视图未附着时跳过选择菜单记 debug：平台拆除或重建视图时的正常退化。

## Risks / Trade-offs

- [提示改用应用上下文，外观是否变化] → 应用主题与界面主题同源（同一 `Theme.Terminal`），
  平台提示布局与文字外观取自系统样式，外观一致。
- [分级判据散落在多处，可能再次分叉] → 每处判据都抽成纯函数并有单元测试钉住。
