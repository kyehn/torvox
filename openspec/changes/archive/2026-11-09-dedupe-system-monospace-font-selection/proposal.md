# Proposal

## Why

模拟器 logcat 里，系统等宽字族的选取日志在一次启动内出现五次：

```
D/native::render::font::font_db: FONT_SELECT: fonts.xml monospace id=ID(InnerId(1v1)) stem='DroidSansMono'
```

五次取值完全相同：重复下发系统等宽字族时，终端每次都重扫字体库、重新解析
fonts.xml 声明的等宽族，并把同一条选择日志再记一遍。

重复下发的来源是三条并行路径（设置应用、字体应用与会话状态发射），启动阶段它们
都会下发同一个系统等宽字族。重扫得到的是同一个面，那行日志也不带新信息——把
「重复下发」当成「每次都要重新解析」，既白扫一次字体库，也让 logcat 里出现
无法解释的重复行。

## What Changes

- 字体管线记住当前字面是否就是系统等宽面：已是系统等宽面时再选系统等宽字族是
  空操作，不再重扫字体库，也不再重复记录该选择。
- 切到用户字族时清除该标记：切回系统等宽字族时重新解析并记录（此时主字体确实
  变了，记录是必要的）。
- 不改公开 API，不改字体解析与选取的判定口径。

## Capabilities

### Added Capabilities

- `logcat-hygiene`：新增「系统等宽字族的重复下发不得重复解析」要求。
