## ADDED Requirements

### Requirement: 解析结论缓存的读取不得以样式或回退层为条件

「某个码位由哪个面的哪个字形解析」这一**结论** MUST 与样式无关、与「装没装 CJK
回退层」无关：粗体/斜体是对光栅化后的遮罩做的后处理，用的还是同一个字形号；
回退层只是解析途径之一，而缓存记的是结论。

结论缓存的读取 MUST NOT 挂在 `has_cjk_fallback` 或 `!synthesized` 之类的条件上。
读取条件 MUST 与写入条件一致，否则会出现「结论只写不读」：没装回退层时（设备上
「主字体已覆盖 CJK」即走这条路）全库扫描是唯一出路，扫描结论写进表却不被读，
同一个码位每出现一次就重扫一遍全库——`find_glyph_anywhere` 要遍历 fontdb 全部
face 并逐个 `with_face_data` 重建 charmap，是毫秒级开销。

伪字形 MUST NOT 入缓存，MUST NOT 从缓存命中返回：字形号 0 是 `.notdef`（非空的
空心方框），私用区码位在主字体上多为 `.notdef`。一旦入缓存，「主字体没有这个码位」
就会被当成已解析，整条回退链被跳过。

#### Scenario: 没装回退层时结论仍被复用

- **WHEN** 主字体不覆盖某码位、未装 CJK 回退层，库内其他面能解析它
- **THEN** 第一次解析走全库扫描，第二次解析 MUST 命中结论缓存，
      MUST NOT 再次触发全库扫描

#### Scenario: 粗体文本复用同一结论

- **WHEN** 某码位以常规样式解析过并记入结论缓存，随后以粗体请求
- **THEN** MUST 命中同一结论（字形号相同），MUST NOT 重新走回退链或全库扫描

#### Scenario: 伪字形不被当成已解析

- **WHEN** 主字体对某码位只给出字形号 0
- **THEN** 该码位 MUST NOT 记入结论缓存，后续解析 MUST 继续走回退链或全库扫描
