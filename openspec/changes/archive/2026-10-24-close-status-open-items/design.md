# Design

## Context

本 change 收口 `docs/STATUS.md` 里剩下的四项「未被解决的问题」。动机见 `proposal.md - Why`，
这里只写约束当前做法的现状与边界。

三条实现链路互相独立，但都遵循同一条纪律：**判别力放在最靠近根因的那一层**。

1. 选择手柄拖动：Android 侧 `TerminalSurface` 负责触点 → 网格坐标折算，
   `TerminalViewModel` / `SelectionManager` 负责选区状态机（含交叉翻转），
   Rust 侧只接收最终边界并做反色高亮。
2. 搜索高亮：Rust `native/src/android/ffi.rs` 的 `applySearchHighlights` 负责
   把上游 `search::Search` 的命中折算成渲染器的高亮列表（含视口裁剪与配色）。
3. kitty 图像：Rust `ghostty_terminal` 维护「图像放置集合」与「Unicode 占位符扫描缓存」，
   Android 侧渲染线程按放置列表画叠加层。

约束：

- 拖动的每个 MOVE 帧必须零同步 JNI 往返（拖动会话把 VT 状态快照化），
  所以触点折算只能是纯函数，才可被 JVM 单测穷举。
- 宽字符吸附的事实来源是原生 `Bridge.wideCharTailCols`，不能由行文本字符位置反推
  （宽字符尾格在文本里是真空白，反推必然出错）。
- Rust 侧放置查询走 `query_tx` 通道，渲染线程与 VT 线程分离；
  缓存失效必须表现为「多扫了行」而不是「画错了」。
- `docs/STATUS.md` 与 `docs/specification/` 是受保护文件，改动实际内容需用户明确同意，
  因此证据留档只能落在 openspec 内。
- 验证环境：x86_64 模拟器（软件 Vulkan）；工具链为 `cargo test --lib`、
  `:app:testDebugUnitTest`、`:app:connectedDebugAndroidTest`；真机（Mali）无法在本轮复测。

既有规范落点：`text-selection` 的「控制柄拖动」、`kitty-graphics` 的「放置缓存按内容变化失效」
与「视口滚动只平移放置缓存」、`text-search` 的「搜索高亮由原生按上游命中直接生成」
与「视口外的命中一律裁掉」。

## Goals / Non-Goals

**Goals:**

- 四项各有一个可复核的自动化判据（用例名 + 计量），并有对应的规范条目。
- 手柄触点折算只有**一个口径**，快速路径与边缘滚动路径共用。
- 折算与配色逻辑抽成可表驱动验证的纯函数，边界（视口外、交叉、网格钳位）可穷举。
- 判别力放在根因层：VT 不变式放 Rust 用例，像素与边界放仪器化用例。

**Non-Goals:**

- 不改 `docs/STATUS.md`、`docs/specification/` 的实际内容（受保护，需用户明确同意）。
- 不改 `text-search` 主 spec：其行为与既有规范一致，本轮只重构可测性。
- 不引入新依赖，不 vendor 可从外部获取的测试数据；不新增测试夹具文件。
- 不重设计选择手势语义（多选、块选、词选择均不在范围）。
- 不追求在模拟器上消灭慢帧日志：软件 Vulkan 的帧耗时分布与真机不同，另行复测。

## Decisions

### 决策一：触点折算的参考点在抓柄时锁定，归属翻转只换角色

**现状缺陷**：触点列原先按「当前这根手柄是哪一侧」选参考点（首端柄 = 首格左缘，
末端柄 = 末格右缘）。手柄越过对侧后归属翻转，参考点跟着换，目标列在翻转瞬间跳一格：
被拖的边界反向移动一格、交叉被立刻撤销（选区塌成单格）、手柄与手指脱开。

**决策**：抓柄瞬间（`latchDragAnchor`）记下 `dragAnchorIsStart`，整次手势内不再变化。
目标列 = `anchorCol + round((touchX - referenceLocalX) / cellWidth)`，
其中 `referenceLocalX = (anchorIsStart ? anchorCol : anchorCol + 1) * cellWidth`，
结果钳位到 `[0, cols - 1]`。归属翻转只改变「这根柄现在扮演首端还是末端」，
不改变参考点，也不改变锚点格。

**备选与否决理由**：

- *参考点随归属翻转*（旧行为）：否决——翻转瞬间目标列跳一格，正是缺陷本身。
- *每次 MOVE 直接取「手指所在格」*：否决——宽字符吸附与翻转语义被混在一起；
  且手指进出边缘滚动区时列会跳一格，与快速路径口径分裂。
- *浮点 grabOffset（termlib 做法）*：不采用——我们要的是整格吸附语义，
  浮点偏移会引入亚格漂移，需要额外的像素级判据才能兜住；整格版本已足够。

**对标**：connectbot/termlib 的 `Terminal.kt` 在抓柄时固定 `grabOffset`，参考点不随归属翻转；
本决策与其语义一致，但落到网格整格。

**不动的地方**：`SelectionState.applyHandleDrag` 的五元组语义本身正确
（含翻转后的被拖柄归属，越界判据为严格不等——落点恰为锚点时不翻转），保持原样。

**规范落点**：这条语义落在 `text-selection` 的三条需求里——
`控制柄拖动`（实时更新、宽字符吸附、交叉交换归属、菜单隐藏与重显）、
`手柄交叉时的触点折算`（参考点锁定、被拖边界跟手、未拖动侧钉住、手柄与边界对齐）、
`抬手帧以最终触点重算`（抬手落点与 `ACTION_CANCEL`）。
原来挤在一条需求里的「抬手帧」与「触点折算」被拆出来：一条需求只说一件事，
正文也不得过长（校验器对超长需求正文告警）。

### 决策二：折算与配色抽成纯函数，判别力放 JVM 单测与 Rust 表驱动测试

- `dragTargetColumn` / `dragTargetRow` 是 `TerminalSurface.kt` 顶层的 internal 纯函数：
  入参为锚点、触点、单元格尺寸、网格尺寸，出参为钳位后的目标行列。
- 快速路径 `dragTargetFromTouch` 与边缘滚动路径 `updateDragHandleForCell` 共用同一折算，
  口径分裂从结构上被消除（原先后者用「手指所在格」，进出边缘区必跳一格）。
- Rust 侧新增 `build_search_highlights(matches, selected, viewport_top, grid_rows, palette)`：
  把 `applySearchHighlights` 里的视口裁剪与配色折算抽成纯函数，**行为不变**
  （当前命中 alpha 255 + 前景色 `0xEEEEEE`；其余命中 alpha 160 + 选区色 `0x334455`；
  视口外的命中在上下两侧裁掉）。

**备选与否决理由**：直接在 JNI 入口里写断言——否决，JNI 路径不便表驱动，
「视口外命中两侧裁剪」这类边界无法穷举；抽纯函数后一屏内即可覆盖。

### 决策三：kitty 清屏的判别力放在 VT 侧不变式，不放在渲染侧兜底

**根因**：ED2 清屏时 VT 侧未撤下图像放置集合，渲染侧无从知道该擦掉哪块像素，
只能靠「整帧重绘」兜底——而累加器里的残留像素要等下一次真正的全量重绘才被抹掉，
表现为「要 clear 两次才消失」。

**决策**：ED2 在**同一次清除内**撤下全部图像放置（直接放置通道 `a=T` 与 Unicode 占位符通道
共用撤除语义）。判别力分两层：

- Rust：`ed2_removes_kitty_placements_on_first_clear` 断言 ED2 之后放置集合**立即为空**。
- Android：`clear_erases_image_on_first_ed2` 做像素级判据，断言屏幕上图像像素不再出现。

**备选与否决理由**：渲染侧收到 ED2 就强制整帧重绘——否决，那只是兜底：
VT 仍留着放置，图像状态仍在，且把「叠加层不得强制整帧重绘」的既有规范架空。

### 决策四：占位符扫描按绝对行缓存，基准取 VT 滚动条给出的绝对行号

**根因**：回看历史时占位符缓存以「回滚长度 + 视口行」为基准，与 VT 实际行号错位，
缓存整体落空，每帧退化为全量重扫——这正是滚动卡顿的来源。

**决策**：

- 逐行签名只含行内布局（列、字素簇续接记号、前景色、下划线色），**不含视口行号**：
  纯滚动时同一绝对行的内容与签名都不变。
- 视口签名 = 合并逐行签名 + 视口顶行的绝对行号。
- VT 侧按**绝对行**命中缓存；基准取 VT 滚动条给出的绝对行号。

**判别力**：`take_kitty_scan_stats()` 由扫描路径自己记账（扫描行数、命中行数），
缓存失效会立刻表现为扫描行数不为 0。两个 Rust 用例分别钉住
「同布局重查不重扫」与「回看历史命中缓存」。

**备选与否决理由**：按视口行号缓存——否决，纯滚动时视口行号全变，缓存恒失效。

### 决策五：证据基线按分支拓扑归属，不把修复前的日志当成现状

用户提供的第三份 logcat 采自 `origin/kyehn-patch-4`，该分支不含占位符缓存修复，
故其中的慢帧记录属于**修复前**基线；修复后构建的滚动循环窗口计量为 `avg=0.61ms`。
留档只写这一事实与计量，不把修复前日志行原样抄进仓库。

### 决策六：证据落 openspec 留档，不改受保护文档

`docs/STATUS.md` 与 `docs/specification/` 的实际内容改动需用户明确同意，故四项的
「状态 / 自动化判据 / 剩余条件」写进本 change 的 `status-disposition.md`，随 change 归档。
内容纪律：只写结论、用例名与计量；不写原始日志行、时间戳、PID 与设备标识。

## Risks / Trade-offs

- **锚点是抓柄瞬间的快照**：若选区因外部原因改变（PTY 输出推挤行号），
  锚点行/列仍是旧值，目标格可能落在旧行上。
  → 缓解：拖动期间 `setSelectionDragging(true)` 抑制新输出引起的滚动复位；
  边缘滚动路径每步重取绝对行号再折算。
- **整格折算对亚格位移不敏感**：手指在格内移动不足半格时目标格不变。
  → 缓解：这是既有整格语义而非回归；像素级判据只断言跨格后的边界位置。
- **纯函数放在已很长的 `TerminalSurface.kt` 顶层**：有膨胀该文件的观感。
  → 缓解：函数保持小而纯，单测独立成 `DragTargetCellTest.kt`；不引入新的抽象层。
- **缓存按绝对行依赖 VT 滚动条与渲染视口顶行一致**：不一致时退化为全量重扫
  （性能退化，不影响正确性）。
  → 缓解：`take_kitty_scan_stats()` 让退化可观测；回看历史的绝对行已有专门用例钉住。
- **清屏撤下放置后，客户端在 ED2 之后重放同一图像 id 才会再次显示**：
  这符合 kitty 协议语义（放置由客户端重发），不是回归。
  → 缓解：像素级用例只断言「ED2 后图像消失」，不断言重放行为。
- **手柄语义变更可能影响既有依赖翻转的交互**：跨过对侧后不再自动撤销交叉，
  这是规范明确要求的新语义。
  → 缓解：既有的「交叉交换归属」场景仍在，仪器化用例覆盖交叉前后两态。

## Migration Plan

- 无数据迁移、无配置变更、无新依赖、无 ABI 变更（新增的都是仓内内部函数与测试）。
- 发布为单个仓库提交序列，各步可独立回滚：
  `0fc30bfd`（搜索导航与视口裁剪）→ `cce34021`（占位符绝对行缓存）→
  `d61032db`（ED2 撤下放置）→ `aff15506`（搜索高亮纯函数与判别力测试）→
  `b4517239`（手柄参考点锁定）。
- 回滚策略：逐提交 `git revert`，不产生需要清理的残留状态。
