# Proposal

## Why

一次覆盖全部代码与文档的全量审查发现，代码健康度规约只覆盖重复夹具、依赖活跃度与扫描
留档，四条本应可复核的约束长期不可判定：

- 样式规范规定代码量不得超过两个参考项目之和，但仓库没有定义「代码量」的口径，也没有
  把它做成可复算的门禁。按统一源码行数口径，生产代码低于两者生产之和，源码合计却高出
  约 39%，同一约束因口径不同而结论相反。
- 历史变更以固定阈值拆分了原生侧大文件，同一阈值从未应用到界面与运行时侧的 Kotlin
  源码，最大文件已达五千余行，既不如自身历史标准，也不如按职责分层的参考项目。
- 设计文档明列三个参考项目，参考资料目录只有其中两个的深度留档，同类度最高的那个缺失。
- 测试规范声明的重复检测与代码质量扫描工具没有进入验证脚本与持续集成，规范声明与门禁
  实际内容不一致，前两条约束因此长期未被自动拦截。

这四条都是「不如参考项目、也不如自身规范」的落差，且都能靠文档与规约把判定口径钉死，
不需要改实现。

## What Changes

- 新增一份全量审查留档，记录覆盖证据、统一口径的量化对照、参考项目实践、逐条判定与
  明确不作处置的边界。
- 在 `code-health` 能力新增四条要求：规模约束的统一口径与可复算留档、超大文件阈值跨
  源码语言一致应用、明列参考项目的研究留档齐备性、声明工具与验证门禁的一致性。
- 把需要改动受保护目录、受保护脚本或源码的事项登记为待办，注明授权前置条件；本次只
  交付文档与规约，不改实现。
- 不改状态文档、不改任何受保护文件的实际内容、不改源码与测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `code-health`：新增四条可复核要求，把规模口径、跨语言超大文件治理、参考留档齐备性
  与门禁一致性纳入判定范围。

## Impact

- `docs/audit/reference-code-health-review.md`：全量审查留档与逐条判定表。
- `openspec/changes/2026-11-08-code-health-reference-review/`：提案、设计、任务与规约增量。
- `openspec/specs/code-health/spec.md`：归档时同步新增四条要求。
- `docs/specification/STYLE.md`、`docs/specification/TESTING.md`、`scripts/check.nu`、
  `.github/workflows/`、`docs/persistence/`：均为受保护文件，本次不修改，仅登记待办。
