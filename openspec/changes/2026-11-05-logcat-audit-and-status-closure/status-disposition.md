# 状态与告警逐条处置

## 一、本轮 logcat 的 W/E 条目归因

审计对象为两份真机 logcat。条目按「应用自身／上游终端／平台／外部程序」逐类归因。原始日志
未入库，总数不可凭记忆补写，故只记逐类结论与结构性倍数关系；不记原始日志行、时间戳、PID 与
设备标识。

| 类别 | 条目 | 归因 | 处置 |
| --- | --- | --- | --- |
| 平台 | 文档提供者查询失败的 W 级告警 | 平台文档提供者在自身 catch 块打印：本仓提供者按 AOSP 契约对不存在的 docId 抛 `FileNotFoundException`，客户端（外部编辑器的「替换保存」流程）回查尚未创建的让位文件与已改名的原 docId 各触发一次缺失查询，故按流程成组出现 | 契约正确，不改语义：改抛空游标或占位行会把「文档不存在」伪装成「文档存在但没有内容」。补一条用例钉住该路径 |
| 平台 | 帧时间线同步组查询失败的 E 级告警 | 平台的帧时间线机制产生，应用无对应调用；按表面重建成组出现，序号随已建立的同步组递增 | 无应用侧动作，不绕过 |
| 平台 | 设备图形分配器的 R8 格式告警 | 厂商 Vulkan 驱动在创建交换链时枚举格式并试分配 R8 格式，厂商分配器不支持该格式；试分配失败后交换链仍以 8 位 RGBA 族建立、帧照常呈现，故每次表面重建固定一组 | 应用侧无可用开关；交换链格式仍只接受三通道以上，单通道与双通道格式一律不选 |
| 平台 | 渲染后端的能力提示缺失（表面视图格式能力位） | 由适配器与驱动决定，渲染后端据此提示非完全合规实现 | 应用侧无可用开关 |
| 平台 | 系统窗口事务的 Binder 空返回、默认字体重载、设备特性探测、属性读取被拒、压缩包条目缺失、ART 调试代理加载失败 | 平台与系统组件自身行为，应用无对应调用 | 无应用侧动作 |
| 上游终端 | 未实现的 VT 动作告警 | 该序列为 DECSACE（VT420 矩形区域属性），由客户端的屏幕清理流程发出；上游未实现该能力 | 应用不绕过上游、不伪造协议未定义的应答 |
| 上游终端 | kitty 图像的文件介质打不开与随后的错误应答 | 上游按终端进程自己的工作目录解析文件介质路径，客户端给出的路径来自它自己的命令行上下文，两者不在同一目录时必然打不开 | 路径基准由上游决定，应用不改写路径、不伪造文件存在；客户端在介质失败后按协议自行退到可用介质 |
| 应用自身 | 慢帧诊断（帧内分段与渲染分段） | 一次性成本：kitty 图像放置时图集打包与上传约 51ms；诊断本身按 500ms 窗口限频并带窗口内计数 | 单次采样不足以判定持续退化，改动的收益只能靠真机复跑判定，本仓环境无法复现，故不改实现 |
| 应用自身 | 命令通道满的告警 | 通道有界，按窗口累计输出并带窗口内丢弃次数 | 已有规约覆盖（`logcat-hygiene` 的命令入队失败告警限频要求） |
| 外部程序 | 客户端 shell 及其子进程（登录、版本控制、文件浏览、图像工具等）的 SELinux 审计记录与自身告警 | 外部程序在应用沙箱内的正常行为；审计记录由内核 SELinux 打出 | 无应用侧动作 |
| 历史记录 | 资源未关闭的 W 级告警 | 该批日志的时间早于查询侧游标泄漏的修复提交，属旧代码下每次失败查询各漏一个游标的记录 | 已由该修复提交覆盖，无需再改 |

## 二、`docs/STATUS.md` 的「文档提供者找不出 rollback 文件警告」一条

状态：已收口。

上一轮留档把本条挂在「缺原始告警文本，拿到前不改代码」上。本轮拿到原文：告警由平台文档提供者
的 catch 块打印，异常来自本仓提供者按 AOSP 契约抛出的 `FileNotFoundException`；触发条件是外部
编辑器的「替换保存」流程——先回查让位文件（此时尚未创建），再把原文件改名让位、建同名新文件、
删让位文件。回查让位文件与回查已改名的原 docId 各命中一次缺失查询，故该类告警按流程成组出现。

应用侧契约正确且已有用例钉住：缺失文档抛 `FileNotFoundException`；让位文件不出现在子项列表里
（列表出现它会让客户端缓存幽灵行并在删除后回查）。本轮补一条用例钉住「让位文件尚不存在时的
回查」这一路径。

处置：不改运行时行为。改抛空游标或占位行会把「文档不存在」伪装成「文档存在但没有内容」，客户端
据此把新建与改名撞成「路径已存在」；过滤该日志则失去「客户端在回查不存在文档」这一可观测信号。
