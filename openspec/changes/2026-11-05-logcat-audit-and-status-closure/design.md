# Design

## Context

审计对象是两份真机 logcat（2026-11-05）。条目分四类：应用自身输出、上游终端（libghostty-vt）
输出、平台输出、外部程序输出。上一轮已在 `logcat-hygiene` 立下「逐条归因并留档」「平台与驱动侧
给出可复核事实」两条要求，本轮补的是尚未进台账的几类，外加 `docs/STATUS.md` 的 rollback 一条。

参见 proposal.md 的动机说明。

## Goals / Non-Goals

- Goals：给每类条目可复核的归因；把 rollback 一条收口；把「不得绕过」的边界钉进规约。
- Non-Goals：不改上游协议实现；不改框架契约语义；不靠过滤或降级日志让审计变绿。

## Decisions

1. **缺失文档仍抛 `FileNotFoundException`，不改成空游标。** 框架的 W 级告警正由此异常触发；
   改成空游标会让客户端把不存在的路径当成仍存在。备选方案是应用侧拦截该异常并自行应答——跨
   Binder 的客户端拿不到异常语义，且会制造「路径已存在」一类新故障。
2. **kitty 图像的文件介质路径不改写。** 上游按终端进程自己的工作目录解析，客户端给出的路径来自
   它自己的命令行上下文，两者不在同一目录时必然打不开；应用侧改写即制造第二条假路径。规约
   `logcat-hygiene` 的「图像传输介质的路径解析基准由上游决定」已覆盖该边界。
3. **DECSACE（VT420 矩形区域属性）不实现。** 该序列由客户端的屏幕清理流程发出，上游未实现该
   能力；应用侧不绕过上游、不伪造协议未定义的应答。
4. **平台帧时间线的同步组查询告警归为平台条目。** 告警由平台的帧时间线机制产生，应用无对应
   调用；它按表面重建成组出现，与应用自身的表面生命周期无因果关系。
5. **慢帧诊断不据单次采样改实现。** 观测到的长帧出现在 kitty 图像放置时（一次性图集打包与上传），
   不是持续退化；改动的收益只能靠真机复跑判定，本仓环境无法复现，故本轮只留口径。
6. **台账只写聚合结论。** 原始日志未入库，总数不可凭记忆补写；留档写逐类归因与结构性倍数关系
   （如「每次表面重建固定一组」），不写原始行、时间戳、PID 与设备标识。

## Risks / Trade-offs

- 台账随日志批次增长 → 只留聚合口径，不留原始行；每条结论给可复核事实（上游判据位置或框架
  契约条款），使后来者无需重跑取证即可复核。
- 「不改」类结论容易被误读为漏做 → 每条同时写明备选方案与被否掉的理由。
