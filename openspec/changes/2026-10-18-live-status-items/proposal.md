# Proposal

## Why

`docs/STATUS.md` 是维护者手写的**真机待办清单**，当前 7 条。上一变更
（`2026-10-17-status-open-items-closure`）收敛的是**已被删除**的那份
`docs/specification/STATUS.md` 的 11 条现象，与本清单的交集只有「文档提供者的创建/
复制移动/保存超时」「简体中文退格」「文本选择」「启动屏图案与图标」。

本清单里另有**零覆盖**的四类，都在上一变更范围之外：

- 重命名文件卡死：上一变更只处理了重名冲突与「改到自身」，没碰卡死本身。
- 输入光标大小形状不一致、移到文本时字体下降溢出（与 termux 不同）。
- prompt 占满整行时的两条输入法现象：光标不可见（termux 会显示在下一行）、
  输入后全部退格不留下空行（termux 不回收已扩展区域）。
- 启动动画「图案模糊」：上一变更处理的是「用完整图案而非图标」与裁切，没处理模糊。

已经收敛过的那四条同样要在**今天的代码**上复验：它们的证据取自上一变更当时，
清单比它们更早，两者对不上时以复验为准。

## What Changes

逐条查根因、落到代码、留可运行检查，并随修更新 `openspec/specs/**`：

1. 重命名卡死：先取得可复现路径（真机或仪器用例），再定位阻塞点并修根因。
2. 光标形状与降部溢出：几何与度量取自单元格而非字形位图，降部不裁切。
3. prompt 满行：无剩余空间时输入法光标的落位（下一行）与退格后空行是否保留。
4. 图案模糊：启动动画的绘制源与缩放口径。
5. 复验：退格延迟、文本选择、启动屏图案与图标、文档提供者的三个子项。

## 不做

- 不动 `docs/STATUS.md` 的条目（禁改区；增删条目需维护者点头）。
- 不为「依赖第三方文件管理器客户端」的现象臆造兜底代码：无复现样本时登记缺口与
  所需证据，不写猜出来的重试。

## Impact

- 代码：按条落点（`ui/TerminalSurface.kt`、`input/**`、文档提供者、`native/src/render/**`、
  启动屏主题与 drawable），每个提交只碰该条所需的文件。
- 规范：`render-stability`、`cursor-rendering`、`ime-editor-contract`、`text-selection`、
  `documents-provider` 按条更新，保持 specs 与代码同步。
