# terminal-foreground-service Specification

## Purpose

终端在前台服务中维持常驻通知、后台存活与用户可触发的会话退出能力。通知内容与
操作入口以 `docs/specification/DESIGN.md` 的软件要求及 termux-app 行为为准。

## Requirements

### Requirement: 常驻通知显示会话数量

存在活动会话时，应用 MUST 运行前台服务并发布一条常驻通知。通知 MUST 显示当前会话
数量；会话增减后 MUST 更新该数量，降到零时 MUST 停止服务并释放相关资源。

#### Scenario: 单会话通知

- **WHEN** 应用只有一个活动会话
- **THEN** 常驻通知显示单会话状态文案

#### Scenario: 多会话通知

- **WHEN** 应用有三个活动会话
- **THEN** 常驻通知显示会话数量 3

#### Scenario: 最后一个会话关闭

- **WHEN** 最后一个活动会话关闭
- **THEN** 前台服务停止，通知不再常驻

### Requirement: 通知提供唤醒锁与退出入口

常驻通知 MUST 提供“申请唤醒锁”与“退出”两个操作。申请唤醒锁 MUST 获取可续期的
部分唤醒锁，使应用位于后台时会话仍能继续活动；退出 MUST 关闭全部会话并停止前台服务。

#### Scenario: 申请唤醒锁

- **WHEN** 用户点击通知中的“申请唤醒锁”
- **THEN** 应用持有部分唤醒锁，终端在后台仍可继续运行

#### Scenario: 从通知退出

- **WHEN** 用户点击通知中的“退出”
- **THEN** 全部会话关闭，前台服务停止，唤醒锁被释放

### Requirement: 申请通知权限

应用 MUST 在需要发布常驻通知时申请 `POST_NOTIFICATIONS` 运行时权限。权限缺失或被拒绝
MUST NOT 使终端会话崩溃；平台允许前台服务继续时，应用 MUST 保持会话可用。

#### Scenario: 首次启动申请权限

- **WHEN** 应用首次启动且平台需要通知权限
- **THEN** 应用发起一次 `POST_NOTIFICATIONS` 权限请求

#### Scenario: 用户拒绝通知权限

- **WHEN** 用户拒绝通知权限
- **THEN** 终端仍可创建会话并输入，应用不崩溃

### Requirement: 执行锁只在有存活会话时生效

前台服务的执行锁 MUST 只在至少存在一个存活终端会话时持有；
无会话时 MUST 释放唤醒锁与 Wi‑Fi 锁；最后一会话关闭或任务被划去时，
MUST NOT 在无会话时重新获取锁。

#### Scenario: 关闭最后一个会话

- **WHEN** 最后一个会话关闭
- **THEN** 前台服务停止，唤醒锁与 Wi‑Fi 锁释放，进程不再持执行锁

#### Scenario: 任务被划去但会话仍存活

- **WHEN** 后台划去任务时至少一个会话仍存活
- **THEN** 服务 MUST 在灭屏期间保持运行，并重新获取唤醒锁和 Wi-Fi 锁

### Requirement: 唤醒锁超时只作安全网且失效后必须重取

唤醒锁的超时 MUST 只作安全网，不得在会话仍存活时到期后不重取；
在持有锁期间续期，若锁已失效则 MUST 回到获取路径。续期
MUST 在半程、仍有完整救援窗口的时机发生；灭屏期间不得因为
超时而冻结 shell。

#### Scenario: 锁到期后仍有会话

- **WHEN** 唤醒锁因超时失效而平静会话仍存活
- **THEN** 服务重新获取锁，且不留无会话持有锁的间隙

#### Scenario: 续期中断且锁已失效

- **WHEN** 续期尝试发现锁确已失效
- **THEN** 服务回到获取路径，而不是假装持有锁

### Requirement: 灭屏后 Wi‑Fi 锁跟随执行锁策略

在持有网络锁时，平台对 `WIFI_MODE_FULL_HIGH_PERF` 的
低延迟映射 MUST 不使灭屏时的网络锁降级失效：灭屏后终端连接保持，
除非明确超出系统的后台努力限制。不得依赖 PowerManager
的省电模式去自动切换网络策略；灭屏后网络锁的可用性以
保持会话与命令连续性为准。

#### Scenario: 灭屏后省电模式导致断网

- **WHEN** 应用灭屏并进入省电模式且仍有会话
- **THEN** Wi-Fi 连接不主动断开，shell 命令与通信保持可用
