# bootstrap-integrity Specification

## Purpose

引导归档（bootstrap zip）不设置 SHA-256 或其他完整性校验机制。本能力明确禁止把
下载链路、归档内容或随包文件包装成完整性信任根，也禁止在代码、配置或持久化数据中
保存校验值。

## Requirements

### Requirement: 引导归档不做完整性校验

下载与安装流程 MUST NOT 计算或比对 SHA-256、校验和、摘要、签名或其他同类完整性值，
MUST NOT 读取随归档单独发布的校验文件。归档 MUST 按来源与安装流程直接进入
解压和换入阶段。

#### Scenario: 下载归档不计算摘要

- **WHEN** 下载器取得引导归档的完整字节流
- **THEN** 字节流直接写入暂存文件，不计算 SHA-256、校验和或同类摘要

#### Scenario: 安装归档不读取校验文件

- **WHEN** 暂存引导归档进入安装流程
- **THEN** 安装器不查找、不读取也不比对任何单独发布的校验文件

### Requirement: 不保存校验值

代码、默认配置、资源、设置与持久化文件 MUST NOT 保存引导归档的校验值或其派生数据，
MUST NOT 维护需要随归档版本同步更新的哈希常量。

#### Scenario: 仓库中不存在引导哈希

- **WHEN** 审阅下载器、安装器与配置常量
- **THEN** 不存在引导归档哈希、摘要或签名列表，也不存在保存这类值的文件或设置项

#### Scenario: 安装状态不携带校验信息

- **WHEN** 应用完成或失败一次 bootstrap 安装
- **THEN** 应用数据中不写入引导归档校验值或可据此推导校验值的状态

### Requirement: 不把传输安全表述为内容完整性

文档与代码注释 MUST NOT 把 HTTPS、URL 来源或体积限制描述为归档内容完整性保证。
这些措施至多约束传输链路或资源消耗，不能证明归档内容可信。

#### Scenario: HTTPS 不被称为完整性门控

- **WHEN** 审阅下载器注释或用户可见说明
- **THEN** 不出现以 HTTPS、预设 URL 或体积区间充当内容完整性依据的表述
