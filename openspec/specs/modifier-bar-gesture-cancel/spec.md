# modifier-bar-gesture-cancel Specification

## Purpose

修饰键栏位于系统底部手势区，全面上滑与侧缘返回会被系统手势认领，并向应用补发
`ACTION_CANCEL`。按键若不吞掉取消手势，就会在用户意图返回桌面时误发按键序列。
`ModifierBar` 经 `MotionEventAdapter` 丢弃 `ACTION_CANCEL` 并合成 `processCancel`，
使被认领的手势彻底无输出。键栏底边因此允许落入手势区：布局只按导航栏 inset 内缩
（导航栏 inset=0 的纯手势设备上不再出现键栏下空带），静止轻点仍正常触发，起滑点
命中按键的上滑则由取消链路与按下反馈延迟兜底。

## Requirements

### Requirement: 触摸取消不触发按键

修饰键栏按键收到 `ACTION_CANCEL` 时 MUST 吞掉本次手势，不触发任何按键输出、粘滞切换或长按副动作。

#### Scenario: 按键上起滑被系统手势认领

- **WHEN** 在修饰键栏按键上按下后触摸被取消（如底部上滑、侧缘返回被系统认领后向应用下发 `ACTION_CANCEL`）
- **THEN** 按键不触发，修饰状态与终端输入均不变

#### Scenario: 正常点按仍触发

- **WHEN** 在按键上按下后原位抬手（无位移、无取消）
- **THEN** 按键正常触发一次

#### Scenario: 超出 touchSlop 上滑不触发

- **WHEN** 在按键上按下后位移超出 touchSlop 再抬手
- **THEN** 按键不触发（既有滑出取消保持）

### Requirement: 按下反馈不得早于系统手势取消窗口

按键的按下反馈（缩放、底色）MUST NOT 在 `ACTION_DOWN` 立即启动。系统底部上滑先
派发 `ACTION_DOWN`、再把同一手势认领走并补发 `ACTION_CANCEL`；反馈若在取消之前
已经画出一帧，用户看到的是「上滑触发了按键动画」，尽管没有任何按键输出。

反馈的启动 MUST 延迟一段覆盖该取消窗口的时间；取消或滑出 `touchSlop` 时 MUST
回到未按下状态且**不产生动画位移**——复位 MUST 是瞬时的，MUST NOT 以插值反向
播放一遍（先缩后弹同样是位移）。抬手复位 MUST NOT 延迟，反馈仍须短促。

#### Scenario: 底部上滑取消

- **WHEN** 用户在按键上按下后，触摸被系统底部上滑认领并收到 `ACTION_CANCEL`
- **THEN** 按下反馈从未启动，屏幕上看不到缩放或底色变化

#### Scenario: 取消后的复位不得有位移

- **WHEN** 按下反馈已经启动后手势被取消
- **THEN** 按键立即回到未按下外观，过程中不出现反向插值的缩放或底色变化

#### Scenario: 正常按住

- **WHEN** 用户按住按键超过延迟窗口且未滑出 `touchSlop`
- **THEN** 按下反馈正常出现，松手后立即复位

### Requirement: 底部内缩只按导航栏 inset

内容盒底部 MUST 只按导航栏 inset（`navigationBarsPadding`）内缩，MUST NOT 为
全面屏手势区（`safeGestures` 超出导航栏的部分）附加内缩：导航栏 inset 为 0 的
纯手势设备（折叠屏外屏等）上，附加内缩会在键栏下留出一条只有背景色的空带。

键栏底边因此允许落在系统手势区内。手势认领的后果由「触摸取消不触发按键」
Requirement 与按下反馈延迟承担：静止轻点不被系统认领、必须正常触发；起滑点命中
按键的上滑被系统认领时，取消链路必须无输出、无残留动画。

终端 Surface 与键栏覆盖层 MUST 贴内容盒底边（键栏与内容盒之间不得出现任何内缩带），
内容盒底边 MUST 恰在导航栏上沿。

#### Scenario: 导航栏 inset 为 0 的设备无键栏下空带

- **WHEN** 设备使用全面屏手势导航且导航栏 inset 报 0（如 ZTE 折叠屏外屏）
- **THEN** 键栏底边与终端 Surface 底边都落在屏幕底边，键栏下不再出现背景色空带

#### Scenario: 带胶囊条的设备键栏贴导航栏上沿

- **WHEN** 设备导航栏 inset 大于 0
- **THEN** 内容盒底边恰在导航栏上沿，键栏覆盖层底边与内容盒底边齐平

#### Scenario: 手势区内的按键轻点仍触发

- **WHEN** 键位落在系统手势区内，用户在按键上静止按下并抬手
- **THEN** 按键正常触发一次（底部上滑需要位移才会被系统认领，轻点不受影响）

#### Scenario: 起滑点命中按键的上滑被认领

- **WHEN** 用户从某个按键上起滑、向上滑动被系统手势认领并向应用补发 `ACTION_CANCEL`
- **THEN** 按键不触发、无残留动画（由「触摸取消不触发按键」与按下反馈延迟承担）
