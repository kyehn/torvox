# display-adaptation Specification

## Purpose

终端在显示密度、字体缩放、窗口尺寸与输入设备配置变化时必须就地生效，不得依赖
Activity 重建后重新下发；任意合法窗口尺寸（分屏、自由窗口、折叠半屏）都必须能
建出会话。渲染节拍以显示帧回调为唯一来源，帧回调链随活跃度启停，定时闭锁只作
安全网：刷新率与省电策略只影响节拍，不影响呈现正确性。

## Requirements

### Requirement: 配置变化必须就地生效

显示密度、字体缩放、窗口尺寸与输入设备配置的变化 MUST 就地生效，MUST NOT 依赖
Activity 重建后重新下发。已有会话的字体光栅系数、单元格度量与网格 MUST 在变化后与
当前配置一致；会话、PTY 与终端状态 MUST NOT 因这些变化重建。

系统显示大小改变时，`densityDpi` 的比较 MUST 走 `applySettings()` 的同一串行闸
重推渲染契约；已有会话的文字光栅系数与网格 MUST 与新密度一致，会话与 PTY 状态
MUST NOT 重建。配置回调 MUST 记录并比较 `densityDpi`，与夜间模式、字体缩放共用
一次下发。

#### Scenario: 修改系统显示大小

- **WHEN** 应用运行中系统显示大小改变
- **THEN** 终端文字按新密度光栅，网格与字号一致，无需重启会话或改动字号设置

#### Scenario: 接入硬件键盘

- **WHEN** 用户接入或拔出硬件键盘
- **THEN** Activity MUST NOT 因此重建，会话数量、终端状态与输入状态保持不变

#### Scenario: 字体缩放与密度同时变化

- **WHEN** 系统字体缩放改变，随后显示大小也改变
- **THEN** 两次变化各自生效，后一次不会把前一次的光栅系数覆盖回旧值

#### Scenario: 显示大小改变

- **WHEN** 系统显示大小改变且应用未重建
- **THEN** 终端文字按新密度光栅，网格与字号一致，无需重启会话

### Requirement: 任意合法窗口尺寸必须能启动会话

首次建会话 MUST 以当前窗口尺寸为准，MUST NOT 以整块显示尺寸推导最小 Surface 或
像素下界。只有非正尺寸与无法容纳一个单元格的几何可以被拒绝；被拒绝时 MUST 在
窗口尺寸变为合法后自动重试，不要求用户重启应用。合法小窗口（分屏、自由窗口、
折叠半屏）MUST 能建出至少一行一列的会话。

#### Scenario: 分屏冷启动

- **WHEN** 应用在分屏、自由窗口或折叠半屏中以小于半屏的尺寸冷启动
- **THEN** 会话建出，网格至少一行一列，界面不停留在空白

#### Scenario: 小窗口放大

- **WHEN** 小窗口中已建出的会话随后被放大
- **THEN** 网格按新尺寸重算，PTY 行列同步更新，不出现内容错位

### Requirement: 帧回调链必须随活跃度启停

帧回调链 MUST 在没有会话、应用不可见或连续空闲超过阈值且无待消费动画时停止，
MUST 在输出到达、输入写入、搜索或选区变化、恢复前台、会话切换时重启。
MUST NOT 以无条件自投维持链；逐帧动画若存在，MUST 由显式的活跃租约持有者申请帧，
不得依赖链常驻。

帧回调链 MUST 提供与启动成对的停止路径；链常驻的理由 MUST 有代码中真实存在的
字段支撑，无依据的常驻注释 MUST 删除。

#### Scenario: 空闲期零回调

- **WHEN** 终端连续空闲超过阈值且没有待处理动画
- **THEN** 从下一个显示周期起不再投递帧回调，主线程不被逐帧唤醒

#### Scenario: 输出到达即恢复

- **WHEN** 空闲期收到 PTY 输出或用户输入
- **THEN** 帧回调链重启，变化在下一个显示帧上屏，不等待空闲闭锁到期

#### Scenario: 关闭全部会话

- **WHEN** 用户关闭最后一个会话
- **THEN** 帧回调链停止，进程不再按显示帧唤醒主线程

### Requirement: 刷新率与省电只影响节拍不影响正确性

渲染节拍 MUST 以显示帧回调为唯一来源；定时闭锁 MUST 只作安全网，其取值 MUST 按
显示周期倍数描述，MUST NOT 被当作帧预算。应用 MUST NOT 假设固定刷新率，
MUST NOT 以固定帧率声明换取高刷新率。

17ms 与 34ms 等定时闭锁值 MUST 被实现与文档描述为基于显示周期倍数的安全网，
不得被当作帧预算；安全网延长为“大于一个显示周期”是符合规范的实现。主线程被占用
而 Choreographer 静默丢弃帧回调时，定时闭锁 MUST 能接管并产生帧，且单显示周期内
最多输出一帧。

应用 MUST NOT 用 `setFrameRate()` 或等价的帧率声明去强制显示刷新率超过当前设备
能力；终端负载不经常需要 120Hz。`setFrameRate` 的实际执行仍被平台视为偏好，
固定高帧率声明会使应用在空闲时也持续拉高显示刷新率。当前帧驱动已经运行在显示
的实际节拍上，可保持这一策略不变。

#### Scenario: 刷新率切换

- **WHEN** 显示在 60Hz、90Hz 与 120Hz 之间切换
- **THEN** 每个显示帧至多一帧，输入回显与滚动不因切换丢帧或出现成对呈现

#### Scenario: 省电模式

- **WHEN** 系统进入省电模式并限制刷新率上限
- **THEN** 渲染仍正确，空闲期仍停帧，不出现黑屏、卡死或丢帧放大

#### Scenario: 定时闭锁只作安全网

- **WHEN** 显示帧回调链健康
- **THEN** 渲染帧由显示帧唤醒产生，定时闭锁不在同一显示周期内推出第二帧

#### Scenario: 主线程忙导致帧回调静默丢弃

- **WHEN** Choreographer 已静默丢弃一个帧回调
- **THEN** 链新鲜度降级到 17ms 安全网，渲染线程仍可收到唤醒并呈现，
  且不出现成对呈现

#### Scenario: 闭锁超过一个显示周期

- **WHEN** 显示运行在 120Hz
- **THEN** 34ms 安全网（大于一个显示周期）不会与显示帧回调同周期
  推出第二帧；17ms 安全网仍约等于两个显示周期

#### Scenario: 固定帧率声明无效或反向耗电

- **WHEN** 应用曾声明固定 120Hz
- **THEN** 显示仍只按设备实际节拍运行，且空闲继续强制 120Hz
  不会被判定优于按实际节拍运行

### Requirement: 配置变更声明补齐硬件与形态限定符

`configChanges` MUST 包含 `density`、`smallestScreenSize`、`keyboard` 与
`navigation`，与 termux-app、ghostty-android-terminal 的完整声明一致；
已有的 orientation、screenSize、screenLayout、keyboardHidden、uiMode、
fontScale MUST 保留。

#### Scenario: 接入硬件键盘

- **WHEN** 用户接入或拔出硬件键盘
- **THEN** Activity MUST NOT 因此重建，会话数量与终端状态保持不变

### Requirement: 刷新率变化必须重新读取不得当成固定帧预算

刷新率变化时，渲染节拍 MUST 按当前显示实际节拍运行。应用
MUST NOT 将 `Display.getRefreshRate()` 当作硬件帧预算；它只是
当前显示模式的实际报告。主线程根据 vsync 新鲜度切换
闭锁长宽时，MUST 用实际测得的帧回调时间戳做判定，
不得把 60Hz 的 16.7ms 当作当前设备的帧预算。

显示周期 MUST 由相邻两帧回调的实际时间戳差得出并报出；落在可采信区间之外的
间隔（主线程长时间被占用造成的丢帧）MUST NOT 被采信为显示周期。

#### Scenario: 刷新率降低到 60Hz

- **WHEN** 显示模式或用户设置把上限降到 60Hz
- **THEN** 活跃呈现按当前实际显示周期工作，输入回显与滚动降速
  不被当作会话故障

#### Scenario: 固定帧率偏好可能不生效

- **WHEN** 应用设置了高于当前显示能力的帧率
- **THEN** 渲染仍按当前显示的实际节拍运行，而不是反复请求超上限的
  帧率或把降频当作崩溃

#### Scenario: 丢帧不得被当成显示周期

- **WHEN** 主线程被占用使相邻两帧相隔数百毫秒
- **THEN** 该间隔不进入显示周期估计，诊断仍报出此前的实测周期
