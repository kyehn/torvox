# session-liveness Specification

## Purpose

会话存活诊断：把「终端会话概率卡死」从不可诊断的黑盒变成可定位、可恢复的工程问题。
判定以「有工作在途」为前提（空闲不是挂起），按渲染 / VT / 输出投递 / Kotlin 生命周期
四层定位，恢复动作按层级分级，自动关闭按窗口节流。

## Requirements

### Requirement: 挂起判定必须以在途工作为前提

会话存活判定 MUST 以「此刻有工作在途」为前提，MUST NOT 以「一段时间没有进展」作为
挂起证据。

空闲 shell 的 PTY 读取线程阻塞在 `read()` 上、VT 线程阻塞在通道等待上，两者都不推进
任何计数；按「计数未推进」判定会把每个空闲超过阈值的 shell 判死。

各层 MUST 用自己的忙标记表达「正在做什么」：忙标记为「自忙起时刻」的读数，非零即
在途，归零即空闲。忙标记 MUST 是原子量，宿主只读，不取会话锁。

#### Scenario: 空闲会话不被判成挂起

- **WHEN** 会话无输出且无输入，VT 线程阻塞在命令通道等待上、PTY 读取线程阻塞在 `read()` 上
- **THEN** 该会话 MUST NOT 被任何层级判为挂起

#### Scenario: 在途工作超时才算挂起

- **WHEN** VT 线程持有忙标记且超过阈值仍未回到等待
- **THEN** 该会话 MUST 被判为 VT 层挂起，并给出已忙时长

### Requirement: 忙标记的时钟域不得跨语言边界相减

原生侧的忙标记 MUST 以原生单调时钟的读数存储；导出到宿主时 MUST 已换算成**已忙
时长**，MUST NOT 把时刻原样交给宿主再与宿主的时钟相减。

原生与宿主语言的单调时钟基准不同，跨边界相减得到的时长没有意义。已忙时长 MUST 为
0 当且仅当标记未置位（空闲），故「刚置位」也 MUST 给出正值。

#### Scenario: 空闲标记读出零

- **WHEN** 忙标记未置位
- **THEN** 导出给宿主的已忙时长 MUST 为 0

#### Scenario: 刚置位的标记读出正值

- **WHEN** 忙标记刚刚置位
- **THEN** 导出给宿主的已忙时长 MUST 大于 0，MUST NOT 与「空闲」的 0 混淆

### Requirement: 挂起必须可定位到层级

看门狗 MUST 判定挂起发生在哪一层，MUST NOT 只给出一个「挂了」的布尔结论。

层级至少 MUST 覆盖：渲染帧在途、VT 线程在途、PTY 输出投递受阻、Kotlin 生命周期
（渲染线程已死而会话仍在运行）。层级判定 MUST 是纯函数：输入是判定瞬间的快照，
MUST NOT 读时钟或全局状态。

判定 MUST 命中即止，且渲染层优先于其余层——渲染帧在途时其余层的读数多半是它的
下游后果。

#### Scenario: 渲染帧在途被判定为渲染层

- **WHEN** 渲染帧起始时刻早于完成时刻且已超过渲染阈值
- **THEN** 挂起层级 MUST 为渲染层

#### Scenario: 渲染层优先于下游层级

- **WHEN** 渲染层、VT 层与输出投递层的读数同时越过各自阈值
- **THEN** 挂起层级 MUST 为渲染层

#### Scenario: 渲染线程已死判为生命周期层

- **WHEN** 会话仍处于运行态而渲染线程已不存在
- **THEN** 挂起层级 MUST 为 Kotlin 生命周期层

### Requirement: 恢复动作必须按层级分级

挂起后的恢复动作 MUST 由层级决定，MUST NOT 对所有层级一律重启渲染线程。

- 渲染层：MUST 重启渲染线程（渲染线程无状态，重建代价最低）。
- VT 层与输出投递受阻层：MUST 关闭会话，MUST NOT 静默重建——静默重建会丢掉用户的
  shell 状态（工作目录、后台任务、已输入内容），比停在原地更糟。
- 生命周期层：MUST 只记录，MUST NOT 自动处理——Activity 重建、切后台期间不得误杀
  用户的 shell。

#### Scenario: VT 层挂起关闭会话

- **WHEN** 挂起层级为 VT 层
- **THEN** 该会话 MUST 被关闭，MUST NOT 被静默重建

#### Scenario: 输出投递受阻按 VT 层处置

- **WHEN** 挂起层级为输出投递受阻层
- **THEN** 恢复动作 MUST 与 VT 层相同（关闭会话）

#### Scenario: 生命周期层只记录

- **WHEN** 挂起层级为 Kotlin 生命周期层
- **THEN** MUST 只记录诊断，MUST NOT 关闭会话

### Requirement: 自动关闭必须节流

同一会话在节流窗口内 MUST 至多被自动关闭一次。反复关闭又新建会让用户看到会话号
乱跳。节流判据 MUST 以该会话上次自动关闭的时刻为基准，MUST NOT 以全局计数器代替。

#### Scenario: 窗口内的再次关闭被挡下

- **WHEN** 该会话刚在节流窗口内被自动关闭过，再次命中关闭条件
- **THEN** MUST NOT 再次关闭该会话

#### Scenario: 窗口过后允许再次关闭

- **WHEN** 距上次自动关闭已超过节流窗口
- **THEN** MUST 允许再次关闭该会话

### Requirement: 挂起判定必须按看门狗实例复核

挂起判定 MUST 携带触发它的看门狗实例。处置方 MUST 在会话锁内复核「本实例仍是该会话
当前的看门狗」；复核未通过时 MUST NOT 处置该会话。

渲染线程重启会换上新的看门狗实例。旧实例的迟到判定若被采纳，会把新的渲染线程标记为
死亡（渲染层），或关闭一个已经恢复的会话（VT 层与输出投递受阻层）。代次闸门只能证明
「该实例自己尚未被停止」，证明不了「它仍是会话当前的看门狗」。

复核与状态变更 MUST 在同一次会话锁获取内完成，两者 MUST NOT 交错。

#### Scenario: 陈旧看门狗的渲染层判定被忽略

- **WHEN** 会话已换上新的看门狗，旧看门狗的迟到判定命中渲染层
- **THEN** MUST NOT 把渲染线程标记为死亡

#### Scenario: 陈旧看门狗的关闭判定被忽略

- **WHEN** 会话已换上新的看门狗，旧看门狗的迟到判定命中 VT 层
- **THEN** MUST NOT 关闭该会话，MUST NOT 领取自动关闭许可

#### Scenario: 当前看门狗的判定仍然生效

- **WHEN** 判定来自该会话当前的看门狗
- **THEN** MUST 按挂起层级执行既定的恢复动作

### Requirement: 挂起回调不得持有看门狗闸门锁

看门狗 MUST 在闸门锁之外调用挂起处置回调。回调取会话锁时 MUST NOT 持有闸门锁。

处置回调要取会话锁（复核身份、领取关闭许可、关闭会话），而看门狗的停止是在持有会话锁
的路径上被调用的——它要取闸门锁。持闸门锁回调即成 AB-BA 死锁：看门狗线程持闸门锁等
会话锁，会话线程持会话锁等闸门锁，整个会话子系统冻住。锁序 MUST 固定为「会话锁 →
闸门锁」。

#### Scenario: 持会话锁停止看门狗不会与回调互等

- **WHEN** 一个线程持有会话锁调用看门狗的停止，同时看门狗线程正在进入挂起回调
- **THEN** 两个线程 MUST NOT 互相等待，挂起回调 MUST 能够完成

### Requirement: 挂起关闭路径必须先停渲染线程再销毁原生会话

因挂起而关闭会话时，MUST 先停止该会话的渲染线程；MUST NOT 在渲染线程仍可能触碰原生
会话时销毁它。

挂起层级为 VT 层与输出投递受阻层时，渲染线程仍卡在原生代码里，它随时可能回到那段
代码继续触碰 bridge 与 surface，此时销毁原生会话即 use-after-free。渲染线程未能在停止
超时内退出时，MUST 跳过销毁并记录错误日志，原生会话待进程消亡时回收。

#### Scenario: 渲染线程仍在时跳过销毁

- **WHEN** 挂起关闭路径上渲染线程未能在停止超时内退出
- **THEN** MUST NOT 销毁原生会话，MUST 记录错误日志

#### Scenario: 渲染线程已停时照常销毁

- **WHEN** 挂起关闭路径上渲染线程已确认退出
- **THEN** MUST 照常销毁原生会话
