# kitty-graphics Specification

## Purpose

Kitty 图像协议（APC `ESC_G`）是终端里唯一能显示真实位图的通道：yazi、lsix、
icat、mpv `--vo=kitty` 等都靠它出图。协议本身有两处「必须答对、否则整幅
图都不出现」的关卡：终端应答能力探测（客户端据此决定是否用 kitty 通道），
以及终端自身的单元格像素几何（放置尺寸由它推出）。本规范钉住这两处关卡，
以及叠加层与增量渲染的关系——图像在场时终端不得退化。

## Requirements

### Requirement: 能力探测必须应答并回显被查询的图像 id

终端 MUST 对 kitty 图形能力探测（`ESC_Gi=<id>,s=1,v=1,a=q,t=d,f=24;…`）给出
应答，且应答 MUST 回显被查询的图像 id（形如 `ESC_Gi=<id>;OK ESC\`），MUST NOT
只回一个与请求无关的固定值。

客户端（如 yazi）把应答解析成「`i=<id>` + `OK`/`ERROR`」：id 对不上即判定
「终端不支持 kitty 图像」，图片预览整体不显示——协议层完全正常，功能却全无。

#### Scenario: 客户端按固定 id 探测

- **WHEN** 客户端发出 `ESC_Gi=278941603,s=1,v=1,a=q,t=d,f=24;AAAA ESC\`
- **THEN** 终端回 `ESC_Gi=278941603;OK ESC\`，客户端据此判定支持 kitty 通道

#### Scenario: 共享内存通道不被支持时明确报错

- **WHEN** 客户端用 `t=s`（共享内存）探测
- **THEN** 终端回 `ESC_Gi=<id>;ERROR:…` 之类的明确失败，MUST NOT 无应答
  （无应答会让客户端等到超时才继续）

### Requirement: 单元格像素几何必须先于图像放置就位

终端 MUST 在解析任何 kitty 图像命令之前，把当前网格的单元格像素尺寸
（`cell_width`/`cell_height`）下发给 VT 引擎，MUST NOT 让 VT 在单元格像素
尺寸未知（宽或高为 0）的状态下处理图像放置。

放置的网格尺寸由「终端像素宽 ÷ 列数」推出；该值为 0 时放置被判为不可见，
图像永不显示——协议解析、数据解码、图集打包全部正常，唯独画面上什么都没有。
同一几何还决定鼠标像素映射与 XTWINOPS 尺寸报告。

#### Scenario: 会话启动后收到第一幅图像

- **WHEN** 应用启动完成（网格 45×48、单元格像素 22×49）后，程序送出
  `ESC_Ga=T,f=100,t=d;…` 传输并显示一幅 PNG
- **THEN** 该图像出现在光标所在位置，尺寸按单元格几何换算，MUST NOT 因放置
  尺寸为 0 而不可见

#### Scenario: 网格尺寸未变时几何仍须下发

- **WHEN** 运行期重算网格得到与当前相同的行列（启动路径的常态：会话带着
  默认网格诞生，重算结果与之相同）
- **THEN** 单元格像素尺寸仍被下发到 VT，MUST NOT 因「尺寸没变」而早退
  ——早退会让 VT 停留在「单元格像素为 0」的状态，图像随即不可见

### Requirement: 图像叠加层不得强制整帧重绘

渲染门控 MUST 只在 kitty 叠加层**本帧发生变化**（新增/替换/删除图像）时
强制整帧重绘；叠加层保持不变时 MUST 允许文本层照旧走脏带增量渲染。

叠加层是独立图集，每帧整层重画在累加器之上，文本层互不影响。此前把
「本帧存在图像」当作必须整帧重绘的理由，等于让**一张静止的图片**把终端
钉在全量帧的代价上（软件渲染设备上全量帧约 500ms → 1-2fps），全屏 TUI
（yazi 等）几乎不可用。

#### Scenario: 图像静止时保持帧率

- **WHEN** 终端上有一幅静止的 kitty 图像，文本持续变化
- **THEN** 渲染循环维持增量帧率（≥ 20fps），MUST NOT 塌到全量帧的 1-2fps

#### Scenario: 图像被替换时清掉旧像素

- **WHEN** 叠加层内容发生变化（同一 id 被新图像替换，或图像被删除）
- **THEN** 该帧整帧重绘，上一帧留在累加器里的旧图像像素被清掉，MUST NOT
  留下残影
