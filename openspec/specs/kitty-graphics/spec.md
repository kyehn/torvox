# kitty-graphics Specification

## Purpose

Kitty 图像协议（APC `ESC_G`）是终端里唯一能显示真实位图的通道：yazi、lsix、
icat、mpv `--vo=kitty` 等都靠它出图。协议本身有两处「必须答对、否则整幅
图都不出现」的关卡：终端应答能力探测（客户端据此决定是否用 kitty 通道），
以及终端自身的单元格像素几何（放置尺寸由它推出）。本规范钉住这两处关卡，
以及叠加层与增量渲染的关系——图像在场时终端不得退化。

## Requirements

### Requirement: 能力探测必须应答并回显被查询的图像 id

终端 MUST 对 kitty 图形能力探测（`ESC_Gi=<id>,s=1,v=1,a=q,t=d,f=24;…`）给出
应答，且应答 MUST 回显被查询的图像 id（形如 `ESC_Gi=<id>;OK ESC\`），MUST NOT
只回一个与请求无关的固定值。

客户端（如 yazi）把应答解析成「`i=<id>` + `OK`/`ERROR`」：id 对不上即判定
「终端不支持 kitty 图像」，图片预览整体不显示——协议层完全正常，功能却全无。

#### Scenario: 客户端按固定 id 探测

- **WHEN** 客户端发出 `ESC_Gi=278941603,s=1,v=1,a=q,t=d,f=24;AAAA ESC\`
- **THEN** 终端回 `ESC_Gi=278941603;OK ESC\`，客户端据此判定支持 kitty 通道

#### Scenario: 共享内存与文件介质已启用

- **WHEN** 客户端用 `t=s`（共享内存）或 `t=f`（文件）传输图像
- **THEN** 终端在平台支持时按该介质读取并显示图像；不支持时回
  `ESC_Gi=<id>;ERROR:…` 明确失败，MUST NOT 无应答
  （无应答会让客户端等到超时才继续）

### Requirement: 单元格像素几何必须先于图像放置就位

终端 MUST 在解析任何 kitty 图像命令之前，把当前网格的单元格像素尺寸
（`cell_width`/`cell_height`）下发给 VT 引擎，MUST NOT 让 VT 在单元格像素
尺寸未知（宽或高为 0）的状态下处理图像放置。

放置的网格尺寸由「终端像素宽 ÷ 列数」推出；该值为 0 时放置被判为不可见，
图像永不显示——协议解析、数据解码、图集打包全部正常，唯独画面上什么都没有。
同一几何还决定鼠标像素映射与 XTWINOPS 尺寸报告。

#### Scenario: 会话启动后收到第一幅图像

- **WHEN** 应用启动完成（网格 45×48、单元格像素 22×49）后，程序送出
  `ESC_Ga=T,f=100,t=d;…` 传输并显示一幅 PNG
- **THEN** 该图像出现在光标所在位置，尺寸按单元格几何换算，MUST NOT 因放置
  尺寸为 0 而不可见

#### Scenario: 网格尺寸未变时几何仍须下发

- **WHEN** 运行期重算网格得到与当前相同的行列（启动路径的常态：会话带着
  默认网格诞生，重算结果与之相同）
- **THEN** 单元格像素尺寸仍被下发到 VT，MUST NOT 因「尺寸没变」而早退
  ——早退会让 VT 停留在「单元格像素为 0」的状态，图像随即不可见

### Requirement: 图像叠加层不得强制整帧重绘

渲染门控 MUST 只在 kitty 叠加层**本帧发生变化**（新增/替换/删除图像）时
强制整帧重绘；叠加层保持不变时 MUST 允许文本层照旧走脏带增量渲染。

叠加层是独立图集，每帧整层重画在累加器之上，文本层互不影响。此前把
「本帧存在图像」当作必须整帧重绘的理由，等于让**一张静止的图片**把终端
钉在全量帧的代价上（软件渲染设备上全量帧约 500ms → 1-2fps），全屏 TUI
（yazi 等）几乎不可用。

#### Scenario: 图像静止时保持帧率

- **WHEN** 终端上有一幅静止的 kitty 图像，文本持续变化
- **THEN** 渲染循环维持增量帧率（≥ 20fps），MUST NOT 塌到全量帧的 1-2fps

#### Scenario: 图像被替换时清掉旧像素

- **WHEN** 叠加层内容发生变化（同一 id 被新图像替换，或图像被删除）
- **THEN** 该帧整帧重绘，上一帧留在累加器里的旧图像像素被清掉，MUST NOT
  留下残影

### Requirement: Unicode 占位符（虚拟放置）必须解码并绘制

终端 MUST 支持 kitty 虚拟放置：扫描视口内带占位符标记的行，解码 `U+10EEEE`
占位符单元的 fg 颜色（图像 id）、underline 颜色（放置 id）与后续组合记号
（图像行、列、高位），按「锚点 = 占位符网格位置 − 图像行列」还原整图左上角，
并 MUST 使用放置自身的 z 值与像素偏移绘制。占位符字形 MUST NOT 作为普通文本
渲染成方框或叉号。

客户端（yazi 等）只发送 `U=1` 与占位符，不发送可见的普通放置；只实现普通
放置会让整幅图不显示，画面上只剩一排占位符字形。

#### Scenario: yazi 的虚拟放置出现在占位符位置

- **WHEN** 客户端发送 `a=T,U=1` 的图像，并在第 2 行第 3 列写入
  `U+10EEEE` + 行列组合记号
- **THEN** 图像左上角出现在该单元（扣除编码的图像行列），MUST NOT 只显示
  占位符字形

#### Scenario: 占位符未编码放置 id 时回退

- **WHEN** 占位符没有 underline 颜色（放置 id 缺省为 0），而该图像存在一个
  `p` 非 0 的虚拟放置
- **THEN** 使用该图像的第一个虚拟放置，MUST NOT 因 id 对不上而丢图

#### Scenario: 占位符移动时图像跟随

- **WHEN** TUI 重绘占位符，把同一幅图移动到新的网格位置（图像 id 与生成戳
  均未变化）
- **THEN** 渲染线程重查放置并把图像画到新位置，MUST NOT 钉在旧位置

### Requirement: 放置缓存按内容变化失效

渲染线程缓存 kitty 放置以减少查询；缓存键 MUST 区分**内容键**（会话、图像生成戳、
可见占位符布局签名、网格行列）与**视口键**（滚动偏移、回滚长度）。

内容键变化 MUST 重查放置：新输出把行推入回滚、TUI 重绘移动占位符、换会话或
resize，都无法用平移表达。漏掉回滚长度时，`kitten icat` 的图像会钉在旧视口行，
后续文本逐行覆盖图像；漏掉占位符签名时，yazi 滚动预览后图像停在旧位置。

#### Scenario: 新输出滚动时图像上移

- **WHEN** 图像显示后程序继续输出，行被推入回滚（滚动偏移仍为 0）
- **THEN** 下一帧重查放置，图像随内容上移，MUST NOT 被新文本覆盖

#### Scenario: 静止图像不触发重复解码

- **WHEN** 图像与占位符布局均未变化，只有普通文本在别处更新
- **THEN** 复用缓存的放置与 RGBA，MUST NOT 每帧重查并重解码整幅图

### Requirement: 视口滚动只平移放置缓存

纯视口滚动的每一帧 MUST NOT 同步查询放置：放置帧是视口相对坐标，按视口顶行
（`回滚长度 - 滚动偏移`）的差量平移已有帧即可，并据此整帧重绘。

每行滚动都同步等一次 VT 查询会让渲染线程按滚动手势的行数排队（真机 yazi 预览
实测约 60ms/行，滚动掉到约 16fps）。

滚动停稳（连续两帧视口键相同）后 MUST 补一次真实查询：平移帧保留的是滚动前
视口的源矩形裁剪，滚动中新露出的边缘只有重查才能补全。该补查 MUST 只发生一次，
随后回到缓存复用。

纯文本会话（生成戳 0）的滚动 MUST NOT 置「叠加层变化」：没有图像可移动，整帧
重绘不会清掉任何图像像素，只会让滚动白白丢掉脏带渲染。

#### Scenario: 连续滚动不逐行同步查询

- **WHEN** 用户在带图像预览的 TUI 中连续滑动多行
- **THEN** 每一行滚动只平移缓存帧，MUST NOT 为每行在渲染线程同步等待一次放置查询

#### Scenario: 滚动停稳后恢复裁剪

- **WHEN** 滚动停在某一行且视口不再变化
- **THEN** 补一次放置查询，图像边缘按最终视口裁剪完整，MUST NOT 缺边

#### Scenario: 纯文本滚动不整帧重绘

- **WHEN** 会话没有任何 kitty 图像，用户滚动回滚区
- **THEN** 不因滚动置「叠加层变化」，文本仍走脏带渲染

### Requirement: 叠加层不得重复混合到自己的旧像素上

叠加层是 alpha 混合。终端 MUST 只在**图像像素被本帧擦掉**的那些行上重画
图像：全量帧整层重画（图像像素必被背景色清除），部分帧只重画与图像相交的
脏带（按像素裁剪），其余像素原样保留在累加器里。

在增量帧里把整层图像重新混合到累加器已有的图像像素上，等于让同一幅半透明
图像反复叠自己：透明度逐帧收敛到不透明（十帧内），半透明图于是「越用越实」，
与「静止图像保持原样」的预期相反。

#### Scenario: 静止的半透明图像长时间不加深

- **WHEN** 终端上有一幅半透明的 kitty 图像，文本在图像所在行之外持续变化
  （触发多轮增量帧）
- **THEN** 图像区域的透明度保持不变，MUST NOT 随帧数增加而变浓

#### Scenario: 脏带触及图像时图像被完整重画

- **WHEN** 增量帧的脏带与图像所在行相交（该处的图像像素被背景色清除）
- **THEN** 该脏带上的图像被重画，MUST NOT 留下被擦掉一半的图像

#### Scenario: 单元格高度未知时保守整层重画

- **WHEN** 单元格像素高度尚未确定（几何未就绪），无法判断脏带是否触及图像
- **THEN** 整层重画图像，MUST NOT 留下残缺图像

### Requirement: 共享内存与文件介质已启用

终端 MUST 在平台支持时启用 Kitty 图像协议的 file 与 shared memory 介质；不支持时
MUST 返回明确错误应答，MUST NOT 无应答。

#### Scenario: 客户端使用文件或共享内存介质

- **WHEN** 客户端用 `t=f` 或 `t=s` 传输图像
- **THEN** 终端在平台支持时按该介质读取并显示图像；不支持时返回
  `ESC_Gi=<id>;ERROR:…`，MUST NOT 无应答
