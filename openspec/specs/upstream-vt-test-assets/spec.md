# upstream-vt-test-assets Specification

## Purpose

把上游终端项目已验证的测试资产以数据形式纳入本项目既有测试体系，使终端状态的分块写入不变性、
跨引擎屏幕一致性与字符宽度分类三处，由上游语料与权威数据而非本地手写构造锁定。

## Requirements

### Requirement: 上游手写种子语料以分块写入不变性锁定解析器

上游 Ghostty 为 libghostty-vt 三个解析入口维护的手写种子语料 MUST 作为本项目解析入口的输入集纳入 `cargo test`。每个种子 MUST 以两种写入方式分别驱动同一规格的终端：一次整块写入，以及逐字节写入并逐块确认排空；两种方式的最终状态 MUST 完全一致。

种子首字节是否为上游 harness 的选择器，MUST 按各 fuzz 入口的实际代码分别判定，MUST NOT 一律处理：`stream-initial` 与 `osc-initial` 的首字节是目标选择器（`stream` 取 `input[0]` 奇偶切换 `nextSlice` 与逐字节 `next`，`osc` 取 `% 3` 选择 BEL/ST/无终止符），不属于 VT 输入，导入时 MUST 已去除；`parser-initial` 的首字节是真实 VT 输入（`fuzz_parser.zig` 不使用 `input[0]`，多数种子以 ESC 开头作为转义序列引入符），该组 MUST 逐字节保持与上游一致。资产说明 MUST 记录该判定与依据，避免把选择器字节当成终端输入，也避免删掉序列引入符使解析器收不到该序列。

语料缺失 MUST 判定失败；任何一个种子在两种写入方式下产生不同状态 MUST 判定失败并给出该种子标识与差异。测试 MUST NOT 依赖未确认排空的写入——本项目 `vt_write` 经有界命令通道投递，突发小写入可被丢弃，未逐块确认会把投递层的丢弃误报为解析缺陷。

#### Scenario: 种子整块写入与逐字节写入结果一致

- **WHEN** 同一份种子字节一次整块写入与逐字节写入（每块确认排空）到两个同规格终端
- **THEN** 两者的网格文本、光标位置、光标可见性、网格尺寸与回滚区完全一致

#### Scenario: 语料目录为空时判定失败

- **WHEN** 种子目录下没有任何文件
- **THEN** 测试判定失败，MUST NOT 报告通过

### Requirement: 真实应用录音以跨引擎一致性锁定屏幕文本

上游 Alacritty 的真实应用输出录音（vim、tmux、交互式 shell、ll 等）MUST 作为语料输入纳入 `cargo test`，并与独立引擎产生的期望屏幕逐行比对，以屏幕文本、行序、光标位置与网格尺寸四项为断言对象。

跨引擎语料 MUST NOT 断言单元样式与回滚区行数：独立引擎与本项目使用不同调色板解算颜色，且两者在回滚上限上的修剪粒度不同，断言这些字段会把解算差异当成终端缺陷。

期望文件缺失或任一行文本不一致 MUST 判定失败并输出应写入的完整期望内容；测试 MUST NOT 提供跳过、忽略或静默重写期望文件。

与独立引擎不一致的录音（如触发列宽切换、选择性擦除、DECALN 等行为差异的样本）MUST NOT 纳入语料，其差异原因 MUST 在资产说明文件中逐份记录，避免用「已知失败」掩盖未知回归。

#### Scenario: 录音产生的屏幕文本与期望不一致时失败

- **WHEN** 某份录音写入终端后采集到的屏幕文本与期望文件任一行不一致
- **THEN** 测试失败，输出期望行与实际行及应写入的完整期望内容

#### Scenario: 跨引擎语料不含样式与回滚断言

- **WHEN** 期望文件含样式或回滚条目
- **THEN** 这些字段 MUST NOT 参与跨引擎语料的判定

### Requirement: 宽度分类与权威 Unicode 数据一致

终端对字符宽度的分类 MUST 与权威宽度数据一致：对全部中日韩表意、音节、兼容表意文字及扩展区段内的码位，引擎给出的单元宽度 MUST 与外部宽度表给出的分类相同。

未分配码位在不同 Unicode 版本间的宽窄归类不一致，MUST NOT 纳入比对；比对的区段 MUST 为已分配且上下界稳定的区段，区段选择理由 MUST 在测试代码中说明。

发生偏离 MUST 判定失败并给出首个偏离的码位及其期望与实际宽度。

#### Scenario: 表意文字区段全部按双宽处理

- **WHEN** 逐字符写入中日韩表意文字区段内的每个已分配码位并采集其占用列数
- **THEN** 每个码位占用两列，与权威宽度表的双宽分类一致

#### Scenario: 出现宽度偏离时报告码位

- **WHEN** 某码位的实际占用列数与权威分类不同
- **THEN** 测试失败并报告该码位、期望宽度与实际宽度

### Requirement: 语料尺寸由期望文件给出

语料运行器 MUST 从期望文件读取终端尺寸与回滚上限后创建终端，MUST NOT 以运行器常量统一规定语料网格尺寸。此约束使不同尺寸的语料共用同一运行路径，并避免为兼容固定尺寸而改造上游输入。

#### Scenario: 不同尺寸语料共用同一运行路径

- **WHEN** 两份期望文件声明不同的行列数
- **THEN** 运行器按各自声明创建终端并分别比对，MUST NOT 因尺寸不同而报错或跳过

### Requirement: 字素簇排布满足三条不变式

终端把码位划分进网格单元的方式决定 emoji、组合附加符与印度语系标记的渲染。引擎在单元层面
并不遵循 UAX #29 的簇边界（见 `terminal-state-regression` 中记录的已知偏离），故此处不断言
簇分组，而断言与分组无关且必须成立的三条排布不变式。

对 UCD 官方 `GraphemeBreakTest.txt`（18.0.0，853 条）每条不含控制码位的用例，引擎排出的网格
MUST 同时满足：

1. **守恒**：权威表中占列的码位在网格里恰好出现一次——不丢、不重。
2. **保序**：按列读回的码位序列是输入码位序列的子序列——不乱序、不凭空产生。
3. **列布局**：单元的列区间自第 0 列起首尾相接，既不留缝也不重叠。

语料 MUST 为 `/tmp/unicode-ucd/GraphemeBreakTest.txt`，由 `flake.nix` 的 shellHook 按固定版本
18.0.0 拉取；MUST NOT 依赖网络。语料缺失、用例总数变动或可比对用例过少 MUST 判定失败，
MUST NOT 跳过或按环境条件裁剪。

含控制码位（CR、LF、NUL）的用例 MUST NOT 纳入比对：UAX #29 的 GB4/GB5 让它们独立成簇并在
两侧断开，但在终端里它们是执行动作而非可见内容，写入后不产生单元，边界期望无法在网格上表达。

单元组成 MUST 经生产渲染通道读取，MUST NOT 使用只为测试服务的快照接口。

#### Scenario: 多簇用例排布满足不变式

- **WHEN** 含多个字素簇的用例（如 `÷ 0061 × 0301 ÷ 1F1E6 × 200D × 2764 ÷`）写入终端并按列读回单元
- **THEN** 占列码位恰好各出现一次，读回序列是输入的子序列，单元列区间首尾相接

#### Scenario: 占列码位丢失时失败

- **WHEN** 某码位的占列次数与输入不符
- **THEN** 测试失败并输出该用例原文、输入占列序列与网格占列序列

#### Scenario: 读回序列出现输入中不存在的码位时失败

- **WHEN** 读回序列不是输入序列的子序列
- **THEN** 测试失败并报告保序不符，附输入与网格两组码位

#### Scenario: 单元列区间不连续时失败

- **WHEN** 某单元的起始列不等于上一单元的结束列
- **THEN** 测试失败并报告该单元实际起始列与应起始列

### Requirement: 宽度核对覆盖较新文种且对分歧做精确集合断言

字符宽度核对 MUST 覆盖较新文种区段（Balinese、Sundanese、Kawi、Nag Mundari）中已全部分配的
连续片段，共 320 个码位，与既有的中日韩区段一并比对，合计 180 694 个码位。

每个参与比对的码位，引擎给出的单元宽度 MUST 与权威宽度表相同；已登记的上游分歧码位 MUST
恰好偏离。登记 MUST 为逐码位的精确集合，MUST NOT 使用区段通配或跳过：引擎出现未登记的偏离
MUST 判定失败；已登记的码位不再偏离 MUST 判定失败并提示删除登记。

区段选择 MUST 只含已分配码位（未分配码位的归类随 Unicode 版本变化），并有断言守住区段划分与
分歧码位的覆盖关系。

#### Scenario: 较新文种区段全部参与比对

- **WHEN** 比对运行
- **THEN** 较新文种区段的 320 个码位全部参与比对，且每个码位要么与权威分类相同，要么属于已登记的分歧集合

#### Scenario: 未登记的偏离使测试失败

- **WHEN** 某码位不在分歧集合内、引擎宽度又与权威分类不同
- **THEN** 测试失败并报告该码位、权威列数与引擎列数

#### Scenario: 已登记的分歧不再成立时失败

- **WHEN** 某码位在分歧集合内但引擎已给出与权威分类相同的宽度
- **THEN** 测试失败并提示上游可能已修复，应删除对应登记

#### Scenario: 分歧集合定义错误时失败

- **WHEN** 分歧集合含重复项，或某登记码位不在任何比对区段内
- **THEN** 测试失败并指出集合定义错误

### Requirement: Kitty 图像解码以真实载荷核对

Kitty 图像解码 MUST 以 Ghostty 上游的真实图像载荷核对，MUST NOT 仅用手写像素：一份 20×15 的
未压缩 RGB 载荷与一份 128×96 的 zlib 压缩 RGB 载荷（后者需跨多块分块传输）。

未压缩载荷解码后的每个像素 MUST 与载荷本身逐字节相同（RGB 归一化为不透明 RGBA）。zlib 载荷
解压后的尺寸 MUST 与声明一致，像素值 MUST 与载荷内容相符，且内容 MUST 为真实图像而非退化
填充。载荷缺失 MUST 判定失败。

传输序列 MUST 声明像素宽高与压缩方式，MUST 按 4096 字节分块且首块携带控制数据。载荷取自
`libghostty-vt-sys` 构建时所用的 ghostty 版本，MUST NOT 取会漂移的分支。

#### Scenario: 未压缩载荷逐像素还原

- **WHEN** 传输 20×15 的未压缩 RGB 载荷
- **THEN** 入库图像的宽高为 20×15，像素数据与载荷按 RGB→不透明 RGBA 展开后完全相同

#### Scenario: zlib 载荷解压为真实内容

- **WHEN** 传输 128×96 的 zlib 载荷
- **THEN** 入库图像宽高为 128×96，像素数据长度为 128×96×4，左上、中部与右下角像素值与载荷内容相符，且不同像素数达到载荷的实际值

#### Scenario: 载荷文件缺失时失败

- **WHEN** 载荷文件缺失
- **THEN** 测试失败并提示先进入开发环境由 shellHook 拉取

### Requirement: 并发不变量测试与单元测试进程隔离

并发不变量用例（shuttle 穷举线程交错）MUST 运行在独立的测试目标中，MUST NOT 与普通单元测试
同进程。

shuttle 在安装全局 panic 钩子时会先访问自身的调度状态，在非 shuttle 线程上触发二次 panic，
从而吞掉同进程内其余测试的真实断言信息。进程隔离 MUST 保证任一单元测试失败时输出其真实断言
内容。

#### Scenario: 单元测试失败显示真实断言

- **WHEN** 任意单元测试断言失败
- **THEN** 失败输出包含该测试的断言内容与实际值，不含第三方库的调度状态错误

#### Scenario: 并发用例保持穷举能力

- **WHEN** 运行并发不变量用例
- **THEN** 两个用例均在独立测试目标中运行并通过，穷举交错的能力保持不变
