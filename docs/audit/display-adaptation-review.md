# 显示适配专项审查

本文审查终端在不同分辨率、刷新率与省电状态下的适配实现，判定标准取 Android 平台口径、
仓库自身规范与参考项目的实际做法。审查只读：不修改源码、测试、脚本、受保护文件与状态
文档。

## 审查范围与覆盖证据

- 基线：远端主分支完整快照。`git ls-files` 计 1302 个文件，其中 1292 个文本文件、
  10 个二进制；逐文件摘要与可执行位和远端 tree 一致。
- 逐文件读取：1292 个文本文件，合计 157068 行、8067082 字节。每个文件按行读取并记录
  行数、字节数与摘要，覆盖率清单可复算，不抽样。
- 规范通读：`docs/specification/` 全部七篇、`AGENTS.md`、`README.md`、状态文档、
  `docs/persistence/` 全部资料；openspec 52 个能力、388 条 Requirement 全清单。
- 参考项目：点名的五个项目全部下载解压；文档中出现过的其余项目补齐 12 份源码与文档
  快照（终端模拟器、终端库、桌面终端与图形栈、测试与截图工具等），另有三份既有缓存
  用于补充对照。托管站拒绝连接的单个终端项目未取得源码，其公开文档仍纳入口径核对。
- 显示适配相关实现逐处阅读：渲染调度与闭锁选择、vsync 帧回调链、Surface 生命周期、
  配置变更处理、设置下发、输入批缓冲、前台服务与电源状态。

## 平台口径

Android 官方文档对刷新率给出三条互相独立的约束：

- 系统可能因省电模式或热节流把显示刷新率限制到 60Hz；应用必须仍能正确工作，不能把
  「请求到的刷新率」当成事实。
- 刷新率不是恒定的。应用若关心它，必须读取当前显示模式并在变化时重新读取，不能写死。
- `setFrameRate()` 只是偏好，平台可以忽略，也可能把显示切到该值的整数倍；事件驱动型
  应用声明固定帧率会持续拉高显示刷新率，反而增加耗电。

配置变更方面，未列入 `configChanges` 的限定符一旦变化就会重建 Activity。`density` 与
`smallestScreenSize` 是两个最容易被漏掉的限定符：前者对应系统「显示大小」设置，后者
对应分屏、自由窗口与折叠屏形态变化。

省电模式方面，平台限制的是刷新率上限与后台执行，不改变应用正确性责任：应用不得依赖
固定帧率，也不得假设 vsync 一定按某个周期投递。

## 本项目的显示适配现状

| 维度 | 实现 | 判定 |
| --- | --- | --- |
| 分辨率 | 网格由物理 Surface 尺寸与单元格度量计算；退化几何钳到至少一行一列；旋转与分屏经 `screenSize` 就地处理 | 计算与 Surface 路径正确 |
| 显示密度 | 光栅系数为 `density × fontScale`，在建会话与配置回调时下发；`density` 未列入 `configChanges` | 存在缺口，见发现 |
| 刷新率 | 单一自调度帧回调按显示帧唤醒渲染线程；健康时闭锁 34ms 作安全网，链停摆时 17ms 兜底，空闲 500ms | 节拍由 vsync 驱动，天然跟随 60/90/120Hz |
| 省电 | 空闲 5s 后停止泵帧；切后台暂停渲染线程；前台服务只为存活会话持有唤醒锁 | 正确性不依赖刷新率，但帧回调链无停止路径 |
| 输入批处理 | 按帧回调合并，另有 50ms 定时兜底 | 与刷新率无关，兜底覆盖回调被丢弃的情形 |

## 与参考项目的对照

| 项目 | 配置变更声明 | 帧驱动 | 空闲行为 |
| --- | --- | --- | --- |
| termux-app | orientation、screenSize、smallestScreenSize、density、screenLayout、keyboard、keyboardHidden、navigation | 输出到达后按需重绘，无逐帧回调 | 零帧回调 |
| ghostty-android-terminal | 与上一行同集合，另含 uiMode | 原生侧按需出帧，无界面层逐帧回调 | 零帧回调 |
| termlib | 组件库，不声明 Activity | Compose 帧时钟，仅在快照到达时请求下一帧 | 无待处理快照即无回调 |
| Drosh | 未声明，配置变化走默认重建 | 自调度帧回调，提供 `start()` 与 `stop()` | 宿主暂停、视图分离、释放时停链 |
| 本项目 | orientation、screenSize、screenLayout、keyboardHidden、uiMode、fontScale | 自调度帧回调，无停止路径 | 链持续按显示帧投递 |

## 发现

### 显示密度变化后已有会话不重新光栅

系统「显示大小」改变时 `density` 变化。`density` 未列入 `configChanges`，Activity 被
重建；运行期是进程级单例，会话与原生渲染器存活下来，但重建路径不重新下发渲染契约。
`onConfigurationChanged` 只比较夜间模式与字体缩放，`applySettings()` 也只有配置回调与
设置变更两个调用点。结果是 Kotlin 侧按新密度计算字号上界与网格，原生仍按旧系数光栅，
终端文字不跟随系统设置，直到用户改动字号或重建会话。

同类故障在字体缩放上已被修复并有注释记录：光栅系数只在建会话与配置回调下发，漏掉
任何一条都会出现「Kotlin 按新系数算、原生按旧值光栅」。密度与字体缩放同属
`density × fontScale` 的两个因子，修复只覆盖了后者。

两个完整的参考终端应用都把 `density` 列入 `configChanges`，不重建 Activity，终端视图
在尺寸变化时重新计算度量。本项目的设计规范也要求正确处理「屏幕旋转、配置变更」，当前
实现只做到了「会话不丢」，没有做到「渲染契约跟随新配置」。

判定：真问题，影响所有修改过显示大小的用户，严重度中。

### 启动尺寸下界按整块显示推导

首次建会话前，启动路径用显示尺寸推导 Surface 下界：宽取显示宽乘以等宽字符宽高比并
钳到 300 至 600 像素，高取显示高的一半并钳到 250 至 500 像素。低于下界即提前退出，
等待一次「正确的尺寸变化」。

该下界衡量的是整块显示，而不是当前窗口。分屏、自由窗口、折叠屏半屏与桌面模式下的
合法小窗口都会被判为过小：会话建不出来，界面停留在空白；只有当窗口随后变大时，尺寸
变化回调才会重试建会话。代码注释已经记录了这一形态（分屏、自由窗口、可折叠半屏），
仪器化测试夹具也用调试属性绕过同一守卫，说明它会挡住合法尺寸。

网格计算本身已把退化几何钳到至少一行一列，启动路径只需拒绝非正尺寸，不需要按显示
尺寸设下限。

判定：真问题，影响小窗口冷启动，严重度中。

### 帧回调链没有启停生命周期

帧回调链在首个会话启动时注册，此后每次回调无条件重新投递自身：无会话时只是读一个空
条目再重投，空闲时跳过唤醒但同样重投。链的注册标志从不复位，关闭全部会话、切后台、
Activity 销毁都不停链。只要进程主线程存活且屏幕点亮，主线程就按显示帧率持续被唤醒，
高刷设备上次数翻倍。

参考项目对同一问题给出两种处理：按需重绘的项目根本没有逐帧回调；采用逐帧回调的项目
提供成对的启动与停止，并在宿主暂停、视图分离、释放时停链。本项目的输入批缓冲也证明
帧回调可能被平台静默丢弃，因此「靠链常驻保证正确性」与「靠平台丢弃省电」互相矛盾：
链既不保证停，也不保证在。

链常驻的理由写在注释里：搜索高亮、选区与闪相位依赖逐帧消费。核对实现后，闪相位字段在
全仓不存在（注释引用了已删除的字段），搜索高亮与选区变更都在原生置脏后由界面侧显式
请求渲染，不依赖链的持续投递。也就是说，当前的常驻没有正确性收益，只剩唤醒成本。

判定：真问题，功耗与设计一致性问题，严重度中。

### 配置变更声明少于参考项目

除 `density` 外，`smallestScreenSize`、`keyboard`、`navigation` 也未声明。三者分别对应
自由窗口缩放、硬件键盘接入与导航方式变化；未声明即重建 Activity，对已经支持硬件键盘
的终端来说是可避免的重建与画面重建。两个完整的参考终端应用都完整覆盖这四项。

判定：真问题，严重度低，与上一条同批修复成本最低。

### 刷新率常量按单一刷新率表述

活跃闭锁的 17ms 与 34ms、新鲜度阈值的 100ms，注释都以 60Hz 周期换算。语义上它们只是
安全网：健康时由 vsync 唤醒，链停摆时才退回定时节拍。规范要求活跃闭锁「明显大于一个
显示周期」，34ms 在 120Hz 上等于四个周期，仍满足要求；17ms 兜底在 120Hz 上等于两个
周期，也仍能保证输入回显。

判定：非缺陷。需要修正的是表述与口径：常量应按「显示周期倍数」描述，避免后来者把它
当成帧预算。

## 逐条判定留档

| 检查项 | 命中 | 判定 |
| --- | --- | --- |
| 刷新率读取 | 生产代码零处 | 非缺陷：节拍由 vsync 驱动，无需自读刷新率 |
| 固定帧率声明 | 零处 | 有意不采纳：与全部参考项目一致，避免持续拉高刷新率 |
| 省电模式读取 | 零处 | 无需读取：正确性不依赖刷新率，平台限频不影响渲染 |
| 帧回调 | 两个文件 | 渲染链缺启停；输入批缓冲有 50ms 定时兜底 |
| 密度使用 | 界面尺寸与字号换算 | 界面正确；原生光栅缺重推 |
| Surface 尺寸变化 | 旋转、分屏、输入法重排 | 路径完整，网格与像素几何都重算 |
| 退化几何 | 网格钳到至少一行一列 | 正确；启动路径的显示尺寸下界是多余限制 |
| 定时节拍常量 | 17ms、34ms、100ms、500ms | 仅安全网与空闲策略，非帧预算 |
| 闪相位字段 | 注释引用，代码不存在 | 文档漂移，已在上文记录 |

## 明确不作处置的项

- 不调用固定帧率声明。终端是事件驱动负载，声明固定高刷会在空闲时也把显示拉到高刷，
  与省电目标相反；参考项目无一采用。
- 不按省电模式切换渲染路径。平台已限制刷新率上限，渲染跟随 vsync 即可正确工作；
  额外分支只会增加未覆盖路径。
- 不为高刷写第二套节拍。vsync 已是唯一节拍源，第二套节拍会在同一显示周期推出两帧。
- 不以截图基线替代节拍验证。节拍与唤醒是时序问题，截图无法证明空闲时没有回调。
- 本次不改源码、Manifest、脚本或受保护文件；修复以规约与任务形式登记。

## 解决方案与优先级

| 优先级 | 事项 | 改动面 | 验证方式 |
| --- | --- | --- | --- |
| 高 | 密度变化重推渲染契约 | Manifest 声明 `density`；配置回调比较 `densityDpi` 并重推光栅系数与网格 | 改显示大小后文字尺寸跟随；单元测试覆盖回调分支 |
| 高 | 小窗口可启动 | 启动路径只拒绝非正尺寸与退化几何，删除按显示尺寸推导的下界 | 分屏与自由窗口冷启动出会话；补仪器化用例 |
| 中 | 帧回调链启停 | 无会话、切后台、空闲超阈值时停链；输出、输入、搜索、选区变更时重启 | 空闲时帧回调计数为零；恢复输出后一帧内出图 |
| 低 | 配置声明补齐 | 补 `smallestScreenSize`、`keyboard`、`navigation` | 接入硬件键盘不重建 Activity |
| 低 | 常量表述 | 注释与规约改为显示周期倍数 | 文档复查 |

## 与 openspec 变更的对应

新增能力 `display-adaptation` 的四条要求分别对应：密度与配置变更的就地生效、任意合法
窗口尺寸可启动、帧回调链随活跃度启停、刷新率与省电只影响节拍不影响正确性。规约增量
只写行为与判据，不写实现细节；实现步骤登记在任务的未完成项中，等授权后另行提交。

## 复现方法

- 密度：应用运行中执行 `adb shell wm density 420`，观察界面缩放而终端文字不变；
  恢复用 `adb shell wm density reset`。
- 小窗口：进入分屏或自由窗口后冷启动应用，观察日志中的「过小 Surface」告警与空白界面。
- 帧回调：空闲时用 `adb shell dumpsys gfxinfo <包名>` 观察帧计数持续增长，或用系统
  跟踪工具统计主线程帧回调。
- 刷新率：`adb shell settings put system peak_refresh_rate 120` 与
  `adb shell settings put system min_refresh_rate 60` 之间切换，观察滚动节拍是否跟随。
- 省电：`adb shell settings put global low_power 1` 后重复滚动与空闲用例，确认无黑屏、
  无丢帧放大。
