## 3. 长按与 libghostty 接口

- 必须用且已用：词派生、跟踪选区、随滚动跟随、复制格式化、超链接查询。优势是单一来源，语义与渲染同源；自研即违规。
- 不得用手势状态机五十项：按下拖动释放深按自动滚动计时手势机与行为表。劣势三条：连击语义与禁止多击正面冲突；边缘定时滚动与动则一行静则零行正面冲突；手势状态若由原生持有则每触摸帧一次跨线程往返，快路径零跨越优势尽失，且与组合手势所有权双状态机脱钩。
- 当前分层合理：原生做派生跟踪格式化，界面侧做手势手柄菜单滚动。十二项小问题的逐项现状见 §3.1。

## 9. 复核轮次的验证记录

第十五轮把前三轮因环境受阻的三项门禁补齐，结论全部有命令输出为据。

- **阻断根因有两处，都不在代码里**。其一：宿主沙箱设了 `TMPDIR` 指向会话临时目录，nix 按 `TMPDIR` 建 shell 目录，故 `NIX_BUILD_TOP` 形如 `/tmp/<会话目录>/nix-shell.XXXX`；而 `native/build.rs` 与 `android/build.gradle.kts` 的「必须跑在 nix develop 内」守卫要求前缀 `/tmp/nix-shell.`。显式 `TMPDIR=/tmp` 后守卫自然通过——nix 在其约定的真实布局下建目录，不是绕过检查。其二：`libghostty-vt-sys` 的构建脚本要从 codeberg 取 `translate-c` 归档，该站点一度整体 503；恢复后 zig 全局缓存自动填充（条目名含内容哈希，不可伪造，也无需伪造）。
- **验证结果**：`cargo check --all-targets`、`cargo clippy --all-targets --deny warnings`、`cargo doc -D warnings`、三组 `cargo bench --quick` 全通过；`cargo test` 572 单测 + 2 并发 + 12 BDD 场景全绿、0 失败 0 忽略；Gradle 侧 `detekt`（117 个 kt 文件零违规）、`spotlessCheck`、`lintVitalRelease`、`testDebugUnitTest`（504 例 0 失败）、`assembleDebugAndroidTest`、`dokkaGenerate` 均 BUILD SUCCESSFUL。
- **两处此前被误判的环境问题**。`NativeBridgeSmokeTest` 十例失败并非代码缺陷，而是 JVM 单元测试从 `native/target/release/libnative.so` 加载**主机**产物；先建 Android 的 `jniLibs` 副本无效，须另建主机 release——这正是 `scripts/check.nu` 里 `cargo build --profile release` 一步的用途。`android/build/reports/problems/problems-report.html` 唯一的 deprecation 来自 `org.jetbrains.dokka:2.3.0-Beta` 调用 Gradle 已弃用的 `Configuration.setVisible(boolean)`，与本仓代码无关，且该文件在 `.gitignore` 排除的构建目录下。
