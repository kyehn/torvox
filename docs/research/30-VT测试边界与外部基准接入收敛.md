# 30 VT 测试边界与外部基准接入收敛

口径：上游为 ghostty `main@main`、kitty、Unicode UCD、esctest/vttest 生态；本仓为 `main` 快照。本文只定"测什么/用什么外部基准/在哪测"的边界，不改 `docs/specification/`。

## 一、VT 测试边界

- **不测**：VT 解析器与终端状态机本身的正确性。该职责已整体委托 `libghostty-vt`（`native/Cargo.toml` 跟踪其 master、无本地补丁），上游有权威 fuzz：`test/fuzz-libghostty` 含 `fuzz_parser.zig`/`fuzz_stream.zig`/`fuzz_osc.zig` 与 `corpus/stream-initial/01..24` 规范种子。本仓再造穷举式 VT 一致性，属 TESTING.md 禁止的「测试依赖行为」。
- **保留**：接缝/契约/回读集成。现有 BDD（`终端回显`、`滚动回滚`、`中文显示宽度`、`窗口标题`、`osc8`、`osc52`）断言的是可观测路径——`写字节 → Ghostty → RenderState 快照 row_text/cursor_row/col/scrollback_length/title/cell 超链接 → 渲染`。它们测本仓接线，而非解析器。
- **为何必须保留**：① 契约断言（首行不被吞、光标跟随、旧行顺序进回滚、汉字占两列，是本仓/规格功能）；② pin 回归绊线——跟 master rev，上游一旦改动本仓依赖的行为，测试立刻红。TESTING.md「不关注依赖小瑕疵」指别把 dep 毛刺当本仓 bug 追，但**因 dep 改动破坏本仓契约而失败，是正当信号**。
- 结论：**不扩张成穷举 VT 一致，保留薄契约/回读绊线**；误删它们会卸掉唯一的依赖回归告警。

## 二、可用的外部基准（界线同上，只测本仓集成/呈现/契约）

### A. 外部标准用例（跑程序/套件，断言可观测回读）

- **esctest / vttest**（DEC/xterm/ECMA-48 权威一致性）：在终端内运行，用现有 `row_text` 抓最终屏，断言 PASS 行 → 全栈（PTY↔Ghostty↔快照↔可选渲染）集成。*交互/有时序，宜放 `connectedDebugAndroidTest` 或取精选子集，不硬塞 `cargo test`。*
- **kitty 键盘协议测试**（kovidgoyal/kitty spec）：对代表性按键×模式，断言本仓经 `libghostty_vt::key` 编码的字节流等于 spec 期望序列 → 测本仓编码器选项接线。
- **Ghostty 自家 fuzz 语料**（`corpus/stream-initial/*`：OSC-title BEL/ST、DCS、APC、hyperlink、clipboard、SGR-256/rgb、scroll-region、C1…）：取子集灌入本仓，按各条意图断言回读 → 零编写把上游规范种子接入本仓集成。

### B. 外部数据即基准（TESTING.md 已在用此法）

- **UAX #11 EastAsianWidth.txt**（Unicode UCD）：数据驱动断言「宽=2 / 组合=0 / 余=1」在采样集上对本仓可观测宽度成立；既是数据流经校验，也是库宽度回归绊线。
- **UAX #29 字素边界**（GraphemeBreak/emoji-data）：断言 ZWJ emoji / VS16 / 组合符落单格，经回读验证。
- **真字体文件 + 真 `/system/etc/fonts.xml`**（已在测）：扩为用字体自带 `hmtx`/`OS/2` 表经 swash 算出的真实 advance 当基准，核对本仓度量；VF `wght/ital` 轴设/复、family 去重对 fonts.xml。
- **真 termux bootstrap zip**（已在测）：扩为装后 `sh -c` 可跑、apt/terminfo 在位。
- **alacritty-theme 仓库**（构建期数据源）：断言解析出的调色板 == 上游主题文件原始字节，守护主题解析。
- **kitty 图形协议样例图/PNG**：喂 spec 样例，经回读 + 像素/OCR 断言放置/ID/尺寸。

### C. 外部参考实现与渲染真值

- **wcwidth / unicode-width / cjkwidth** 参考值表，对本仓观测宽度交叉核对。
- **SGR→颜色**：对本仓 RenderState 解出的 fg/bg，对齐 `xterm-256`/ECMA-48 规范表。
- **金图 + rapidocr OCR + lavapipe**（TESTING.md 工具链）：固定串×主题×字体渲染，OCR 验文字、断言关键像素色 → 测渲染管线对外部真值，而非解析器。

## 三、务实优先级（落进现有体系，不新造框架）

1. Ghostty fuzz 语料精选回放 → `cargo test` BDD（最低成本、直连接缝）。
2. UAX #11 采样数据宽度测试 → 数据驱动、守护最易回归契约。
3. kitty 键盘协议字节断言 → 测本仓编码接线对外部 spec。
4. 扩真实字体/bootstrap 数据 + swash 真度量；金图 OCR 渲染一致性（沿用现有工具链）。
5. 全量一致再考虑 esctest/vttest 放真机 `connectedDebugAndroidTest`，取精选子集而非穷举。

## 四、禁止项勿抄

- 不把外部解析器一致性套件（esctest/vttest 全量、Ghostty 解析器测试）搬进来当本仓测试——违「不测试依赖行为」，且维护负担大。
- 不把 Ghostty/上游的「小瑕疵」转为本仓测试失败；只在本仓**契约/pin 回归**被破坏才判红。
- 不配 TERM/terminfo（PROHIBITED）；不新增独立测试体系；「不崩溃」不算断言、不可 skip、须可复现。
- 外部数据仅作 fixture 真值，不 vendor 成代码引入（BUILD.md）；不用 `git checkout`/`restore` 动会话外文件。

## 六、执行结果（优先级 1–3 已落地）

三项都落进同一个新测试目标 `native/tests/external_benchmarks/`（`support` 取数辅助 + 三个
模块），走 `cargo test`，不进 `cargo bench`、不新增体系。数据一律**运行期现取**：
新增 `ureq` 为 dev-dependency（仅测试用，不进 Android 产物），仓内不留任何数据副本。

### 6.1 UAX #11 全量宽度基准（`unicode_width`）

- 范围比原计划更大：**全部**已分配的可打印码位（`L`/`N`/`P`/`S`，实测 169,799 个）逐个写进
  网格，回读单元宽度与「占位宽度之外必须紧跟分隔空格」。抽样会放过的东西正是这类基准的
  盲区，故不抽样。
- 期望值由同一份 UCD 数据推导（`EastAsianWidth.txt` + `extracted/DerivedGeneralCategory.txt`），
  故用 `latest` 而非钉版本号：UCD 年度发布只会改期望，不会改用例稳定性；真判红即本仓渲染
  与最新版 UCD 不符。
- **实测全量分歧仅 268 个码位（0.16%），全属终端既有惯例**，已逐条钉进用例的例外表：
  韩文组合型字母与填充符（含 U+115F/U+1160/U+3164/U+FFA0，共 242 个）、二倍/三倍长破折号
  （U+2E3A–U+2E3B，字形两格宽）、区域指示符（U+1F1E6–U+1F1FF，国旗 emoji 占两格）。
- 组合符（`Mn`）与零宽惯例码位另立两条：写入「基础字母 + 零宽码位」，断言并入同一格且不占列。
- 变异验证：把宽度判据退化为「一律一列」→ 235,308 处分歧判红；不写零宽码位 → 三条用例全红。

### 6.2 一条被数据逼出来的测试设计约束（值得单记）

零宽回放最初按全量做（2090 个 `Mn` + 244 个惯例码位），结果 debug 档下 **flush 要 14s**，
`take_snapshot` 随即 500ms 超时判红。逐项定位后确认根因**不在本仓代码**：

| 写入内容 | debug 档 | release 档 |
| --- | --- | --- |
| 12500 字节纯 ASCII | 68ms | 9ms |
| 1600 对「基础字母 + 组合符」 | 21s | 1.6ms |
| 1600 个孤立组合符（无基础字母） | 14ms | 1.5ms |

上游 `libghostty-vt-sys` 构建脚本按 cargo 的 `DEBUG` 环境变量选 Zig 的 `-Doptimize`，
debug 档即 `Debug`——**debug `cargo test` 链的是未优化的 Zig 解析器**，合成字素簇那段代码
慢约四个数量级。故组合符回放按等距抽样（上限写在用例常量旁并附实测数字），生产（release）
口径无此问题。附带一条可复用的教训：`pty_write` 按块投递且通道有界，测试里逐码位各投一块
会在排空前被丢弃（那条路径按设计不阻塞调用方），必须整批一次写入。

### 6.3 ghostty fuzz 语料回放（`upstream_corpus`）

- 24 条 `stream-initial` 种子按发布标签取（内容冻结、可复现），逐条灌生产写入路径
  （`pty_write` → VT → 快照），按种子名声明的意图断言回读：网格文本与落点、光标、宽字符续列、
  标题、超链接、剪贴板事件、PTY 回写应答、模式位。
- 语料清单按名排序并断言条数（上游增删时 404 直接判红）；不靠 GitHub API 列目录是为了不把
  未认证限流（60 次/小时/IP）引进 CI。
- 变异验证：只灌首字节 → 判红（「Hello, World!」对不上）；去掉 flush **不**判红——因为
  `TakeSnapshot` 与写入同在一条 FIFO 命令队列上，本就不必等 flush。这条否掉了一个看似该有的断言。
- 过程中的一个实质教训：`14-decset-decrst` 的十六进制要逐字节读——它是
  `?25l` `?1049h` `?25h` `?1049l` 四段**配平**，按名字猜成「关光标两次」就会写出错误的断言。
  该条因此改用**逐字节状态游走**：只断言终态分不出「配平」与「整串 DECSET 被忽略」，必须断言
  中途确实进过备用屏。
- 顺带核实两件事并留档：`mode_get(Mode::ALT_SCREEN)` 恒为假（备用屏不在上游模式表里，生产的
  判据是 `alt_screen_active_atomic`）；DA1/DA2/DA3、DECRQM、DSR、DECRQSS 的回写应答都通，
  唯独 DECRQSS 查 DECSTBM 无应答。

### 6.4 kitty 键盘协议（`keyboard_protocol`）

- 原计划「断言字节流等于 spec 期望序列」照做，但**断言面必须收窄到接线**：字节全部由上游
  `key::Encoder` 产出，本仓只负责把应用的 `CSI > flags u` 请求送进同一个 VT 实例、让编码器
  每次按键从该实例同步选项。此前只有 Escape 一个键在 kitty 模式下被钉住。
- 取样面是 Android 能送出来的键（`keymap.rs` 收录集合），规范里 PUA 段的 F13–F35 与产品面
  无关，不取；规范按发布标签取，功能键表按 `.. csv-table::` 标记解析（含不换行空格归一）。
- 判红即接线断：变异「不送增强请求」后三条用例立刻全红（F1 从 `ESC[P` 退回 `ESC OP`）。
- **查出 16 处上游与规范不一致**，逐条钉住实测值并注明分歧（按第四节「不把上游小瑕疵转为
  本仓失败」）：方向键、Home/End、F1/F2/F4 在 kitty 模式下仍发 legacy 形式（规范要求
  `CSI 1 D` 等）；媒体键与音量键在所有标志组合下都不发字节（规范表列有 `57430 u` 等）；
  只开消除歧义时 CapsLock/NumLock 不发字节（叠加「所有键按转义码上报」后才发 `57358 u`）。

### 6.5 与原计划的口径差异（登记在案）

- 优先级 1 原写「进 BDD」：改为 Rust 集成测试目标。理由是断言要按种子名逐条写代码化的期望，
  塞进 Gherkin 步骤只会多一层无收益的间接；接缝（写字节 → VT → 快照回读）与 BDD 完全相同。
- 优先级 3 原写「测本仓编码接线对外部 spec」：实做时发现字节断言基本落在上游，故改为
  「规范表当真值 + 分歧登记」，接线断言（增强请求是否到达编码器）才是本仓的判据。
- 优先级 2 的「采样」二字作废：可打印码位全量比对，实测开销可接受。
- 优先级 4、5 未动：真实字体/bootstrap 数据扩面与金图 OCR 仍待设备侧工具链，esctest/vttest
  仍按原口径留到真机 `connectedDebugAndroidTest`。
