# Android 终端模拟器生态深度研究报告

25 个参考仓库逐一下载并做代码级审查，与本项目（Rust + libghostty-vt + wgpu Vulkan 渲染 + Kotlin Compose UI 的 Android 终端）对比，找出可参考点与应规避点。

## 0. 范围与方法

- 仓库全部浅克隆到工作区外临时目录，源码逐仓审查：16 个实质仓库做深读（含与上游的 `diff -rq` 血缘比对），9 个小/空/非终端仓库逐文件读完。
- 证据口径：正文引用格式为 `仓库/文件:行号`，均来自实际代码；README 声称但无代码佐证的，明确标注"仅 README 声称"。
- 本项目基线以 `docs/specification/` 为准，现状以仓库实际代码为准。

## 2. 本项目基线

- Rust 侧（约 3 万行）：libghostty-vt 为终端唯一真源；wgpu Vulkan 渲染（字形图集 + cell 实例化 + 自研 WGSL）；PTY、会话、Shell 环境、渲染循环归属 Rust；Kotlin 仅经 JNI 收轻量事件。
- Kotlin 侧（main 约 1.9 万行）：包 `terminal.emulator`，applicationId `com.termux`，Compose UI；SurfaceView 交 Rust 用 ANativeWindow 渲染。
- 关键规范：无 termux-exec/LD_PRELOAD；`TERM=xterm-256color`；回滚 2K；Termux 式选择与修饰键栏；搜索可进回滚区、不支持正则；主题走 alacritty-theme 列表；Bootstrap 运行时安装、旧 usr 随机后缀改名；禁会话持久化/透明背景/proot 内嵌/自定义主题/Shizuku 等。

## 3. 终端核心与 VT 解析

生态共五条路线：

1. **复用 Ghostty**：ghostty-android-terminal（Java + 预编译 `libghostty-vt.a` + Canvas）、本项目（Rust 绑定 + wgpu）。两者证明"不自研 VT"有两个落法，共同点只有 VT 真源。
2. **复用 Termux 库**：RedTerm 经 JitPack 引用 v0.118.3 的 terminal-emulator/terminal-view，自研应用层（多发行版、SSH、录制回放）。第三条路线，但要求接受 Termux 的 Canvas 渲染与 GPL。
3. **Kotlin/Java 自研 VT**：charon（VT500 全状态机 + fuzz + JVM 单测，最完整）、terminator（5177 行，全 OSC 矩阵）、anoterm（761 行最小子集）、puppy/on3（百行级子集，无宽字符）。
4. **Rust 自研 VT**：Rin（545 行手写 ANSI 解析 + portable-pty + Canvas 指针进 Rust 绘制）——证明手写解析器必然是不完备子集，反衬 libghostty-vt 单一来源的价值。
5. **无 VT**：ApexShell（正则染色的 AnnotatedString）、Ply（管道文本）——交互式 TUI 不可用，纯反面。

结论：本项目路线（Ghostty 真源 + 自研渲染）在生态中无第三家；charon 是"若必须自研"时的质量标杆。

## 4. 渲染路径

- 主流是 Canvas 逐格 `drawText`：Termux（TerminalRenderer）、ghostty（`drawRowText` 批处理 + 非 ASCII 强制单画，TerminalView.java:1836-1837）、puppy（onDraw 内 `measureText` + `resize`，反面）、ThothTerm（PaintRenderer + BiDi 分段）。
- GPU 路线仅本项目（wgpu）与 Rin（Canvas 指针进 Rust，仍是 CPU 光栅化）。ghostty 的批处理注释写明了前提假设（等宽 ASCII 的 advance 恰为 cellWidth），该假设正是我们字形图集 + 整形的职责边界。
- 脏跟踪：ghostty 靠 Ghostty 脏区 + snapshot 合并；Rin 用 `mark_dirty`  trait；Termux 靠 `invalidate` 全量。我们的"脏跟踪、跳过干净快照"（DESIGN）与 ghostty 同源，可用其 snapshot 合并逻辑做对照。
- ThothTerm 的 `PaintRenderer.java:57-162` 用 `java.text.Bidi` 做逻辑↔视觉 cell 映射，是全生态唯一 BiDi 实例；本项目规范不含 BiDi，仅记录。

## 5. PTY 与进程模型

- C 层 PTY 高质量共识（on3 `termite.c`、puppy `pty.cpp`、ghostty `pty_jni.c`、Termux `termux.c`）：`/dev/ptmx` + grantpt/unlockpt → `setsid` → slave 建 controlling tty → dup2 → 关 master 端 → 清信号掩码 → 关多余 fd（on3 遍历 `/proc/self/fd`，termite.c:73-84）→ chdir → exec。
- 值得核对的三处细节：
  1. on3 `termite.c:41` 的 `IUTF8`：内核按 UTF-8 处理退格，一次擦一个完整多字节字符——直接对应我们"CJK 退格一次一个汉字"验收；若我们走 Ghostty 输入路径，需保证语义一致。
  2. ghostty `pty_jni.c:104-107` spawn 时 winsize 带像素字段（`ws_xpixel/ypixel`），且 no-op resize 跳过（TerminalSession.java:400-417，防 mksh 的 SIGWINCH 擦行）。
  3. 关会话先 `killpg` 前台进程组再回退（ghostty `ptyHangupForeground`，pty_jni.c:356-380；与 REFERENCE.md 引用的 zed-android-port 做法一致）；puppy `pty.cpp:135-151` 的 HUP→轮询 200ms→KILL 序列。
- 退出码编码共识：signal 终止记负值（Termux `[Process completed (signal N) - press Enter]`，TerminalSession.java:353-361；on3 `waitFor` 返回 `-WTERMSIG`）。我们的崩溃保留现场文案与之对齐。
- 环境变量方向：Termux `TermuxShellEnvironment.java:78-91` 的 LD_LIBRARY_PATH 先设后删、上游整体去 LD 化，印证我们禁 LD_LIBRARY_PATH/LD_PRELOAD；ghostty 只给 `PATH=/system/bin` + 透传 TERM/COLORTERM，与我们白名单思想一致；jolz README 自述"清空环境导致黑屏"的反面教训印证透传 ANDROID_* 的必要。
- AW fork 在 `termux.c:165` 把 `ReleaseStringUTFChars(env, cmd, cmd_cwd)` 写错对象（上游为 `cwd`），JNI 规范违反——fork 改 native 代码必须跑测试的反面教材。

## 6. 字体与 CJK

- ghostty 四槽字体（regular/italic/bold/boldItalic 独立路径）五个缺点已在 REFERENCE.md 点名：心智负担 4 倍、表达不了 variable font/字重、混搭不校验导致 advance 与网格不符、staged-copy 泄漏、存绝对路径。我们单主字体路线正确，不引入。
- anoterm `CharWidth.kt`：结合/格式类用 `Character.getType` 而不用范围表（U+3099 误判教训）；EAW W/F 范围表判宽；ambiguous 默认 1；地域指示符计 1；ZWJ 不组簇。可作为我们 `cjk.rs` 宽表维护的审查项。
- rafacodephi `WcWidth.java:538-583` 修了上游真实 bug：行尾孤立 high surrogate 越界——宽字符边界处理必须有 limit 检查。
- CJK 渲染性能：我们"只加载实际需要字体、退格不卡顿"的要求，在生态中无第二家达标（Canvas 系逐格绘制先天不足）；anoterm 宽 glyph 按 2 倍 cell 居中是 Canvas 系的通用做法。

## 7. 文本选择

- Termux 分层：view 层只给 COPY/PASTE/MORE（TextSelectionCursorController.java:33-35），MORE 转系统 ContextMenu；app 层补全选/分享/打开链接；空白长按仍给粘贴（:118）。与 DESIGN 的菜单规则一致，可作行为验收对照。
- ghostty：选择状态住模拟器（tracked grid refs），Java 只画把手；把手边缘翻转（TerminalView.java:1745-1780）；禁用 GestureDetector 双击检测改用自计数（:499-502，手势坑）；拖拽 reorder + 越界翻转 + 边缘滚动；当前搜索匹配复用 selection 槽实现跟随。
- charon `TextSelection.kt`：选择空间负行号进回滚、软换行 join、跳 WIDE_CONTINUATION、行尾 trim；`wordAt` 按词类不断开路径/URL。
- 链接识别：charon `UrlScanner.kt`（按需扫描、跨软换行、尾随标点裁剪、括号配对）与 REFERENCE.md 引用的 termlib 独立收敛；但 DESIGN 要求"链接经 libghostty-vt 查询、无额外检查"，故自研扫描器不采纳，仅借其选择空间模型。
- DESIGN 禁双击/三击选择（ghostty 有双击选词/三击选行，不抄）。

## 8. 修饰键栏

- Termux 默认布局（2 行 7 列，TermuxPropertyConstants.java:329）照抄；latch 语义为 `readSpecialButton` 的 one-shot（未 lock 读后自清，ExtraKeysView.java:643-655），我们取 tap 单次语义、不取 lock（DESIGN：无双击持久）。
- 滑入文本输入框：Termux 用 `TerminalToolbarViewPager` + 实例状态保存（TermuxActivity.java:192,522-554），与 DESIGN 同构。
- charon 的修饰键三态 + 长按变体 + 自动 repeat（400ms 起 60ms 步进）超出规范复杂度，不抄；其"滑动穿越按键行不取消点击"的判定细节是手势实现的通用知识。

## 9. 文本搜索

- ghostty 搜索是实现级范本：独立 find bar 不改网格（免 SIGWINCH）；单锁内完成扫描+高亮；匹配复用 selection 槽（反色 + 跟随 + 定位）；`MAX_MATCHES` 环形缓冲（5 万上限，扫完转有序，总数永真）；1:1 大小写折叠（ASCII 内联 + BMP 查表，`scripts/gen-case-fold.py` 生成）；定位留 1/4 上下文；`search_dirty` 避免导航重扫。
- RedTerm `SearchHighlightOverlay.kt` 用覆盖层画两层高亮（普通 0x66CDD6F4 / 当前 0xCC89B4FA），与 ghostty 同构，印证 DESIGN 的"匹配反色 + 当前特殊高亮"。
- DESIGN 禁正则（ghostty/terminator 均无正则搜索），上限策略与折叠表是可以直接借用的两项。

## 10. 会话管理与系统集成

- 会话不随 Activity 走是跨生态共识：ghostty SessionManager 进程单例 + `configChanges` 自管旋转；ThothTerm 会话归属前台 Service；我们会话归属 Rust。ghostty `attachSession` 的跨会话状态清空清单（finishSelection/searchClose/清图缓存/reset 输入/scroller 归零）值得对照自查。
- 常驻通知：Termux `startForeground + buildNotification`（TermuxService.java:205-206，含 wake/wifi 锁显示）；我们的 TerminalForegroundService 同类对照。
- DocumentsProvider：Termux（`filepicker/TermuxDocumentsProvider.java`）、kosh（`AlpineDocumentProvider.kt`）均有实现；我们暴露 home 目录，声明对照即可。
- 设置下发模式（两处独立收敛）：monet fork 的"刷新后 reset 全部会话 emulator"（TermuxTerminalSessionActivityClient.java:506-560，由真实 bug 驱动）与 terminator 的"live 设置 vs spawn-time 设置"二分 + collector 推送全部 live 会话（MainViewModel.kt:255-290）。我们的 SettingsRepository→Rust 下发应采用同一模式：主题/字体等 live 设置必须作用于全部会话。
- Android 12+ 幻影进程限制（Termux README NOTICE，issue #2366）：无辜 signal 9 是平台约束，会话放 Rust 侧同样受 cgroup 限制，需如实记录而非掩盖。

## 11. 主题与动态取色

- sohan-f `MonetTerminalColors.java` 是壁纸取色落终端 16 色的完整方法论：HCT 高 chroma 合成语义色 → `Blend.harmonize` 向种子色转 ≤15° → WCAG AA 4.5:1 对比度门 + 去重 + 色相距离门；灰色与前后景保留 Monet neutral；用户 colors.properties 永远优先；API<31 回退 xterm。
- ghostty 无 Monet（自绘主题），ChromePalette 由终端背景派生主屏 chrome——"主题联动"思路可借。
- 我们终端主题走 alacritty-theme 固定列表（DESIGN），Monet 整套不采纳；但"用户文件优先于动态值"与"刷新作用全部会话"两条原则已分别体现在字体设置与上节下发模式中。
- ownerroc 系同源换皮，无额外参考点。

## 12. Bootstrap 与发行版路线

- Termux 原流程：构建时下载 bootstrap zip（sha256 校验，app/build.gradle:170-213）→ 编进 `termux-bootstrap` .so → 运行时解到 staging → `SYMLINKS.txt`（`←` 分隔）建软链 → bin/libexec 设 0700 → renameTo PREFIX → 写环境变量文件。我们的偏离是有意的：运行时 URL/本地安装、旧 usr 随机后缀改名（用户手删）、不记标记、不做 bootstrap 包的 sha256 校验（PROHIBITED）、禁该环境变量文件；**照抄的只有权限设置流程**（DESIGN 原话）。
- puppy（Alpine + proot + marker + 无校验）、kosh（proot/chroot 双模式 + 无版本判断）、RedTerm（多发行版注册表）均为"发行版容器"路线，PROHIBITED 禁内嵌 proot/预装发行版，不采纳；仅 RedTerm 的安装器单测（TarExtractor/RootfsPermissions）可作我们 BootstrapInstaller 测试设计的对照。
- rafacodephi 的 BLAKE3 整包校验（BootstrapIntegrityVerifier）因 PROHIBITED 禁校验而不采纳，记录备查。

## 13. 输入法

- 生态三分：TYPE_NULL 裸键（ghostty、anoterm-raw、charon-raw；TUI 安全但无联想）、全文框镜像（charon-abc：Editable 镜像 + composing diff + 五项填坑 + PredictiveWire 单测，最完整）、系统默认（puppy/on3 的 BaseInputConnection 基础实现）。
- DESIGN 要求"全功能输入法、不限制特性"，方向最接近 charon-abc；其填坑清单（updateSelection 常报、beginBatchEdit 接受、getExtractedText 给镜像、commitCorrection 接受、Android 14 replaceText 路由）应逐项核对我们的 TerminalEditorInfo/ComposingDiff。
- anoterm 的日语视角补两项：空 setComposingText 清 composing（Gboard）、`ACTION_MULTIPLE` 取字（硬键盘）；composing 显示为光标处下划线半透明叠加。
- terminator README 明确提示 local echo/SRM 与 IME 的双字冲突——我们禁 local echo，天然避开。

## 14. 高级特性

- kitty 图像：ghostty（独立 GFX snapshot 通道 + placeholder 归并 + z 序双 pass + vendored stb_image）与 charon（APC 拆分 + Apparitions）均有完整实现；我们已有 render/kitty.rs + kitty_graphics.wgsl，ghostty 的"借用句柄单 JNI 调用内消费"与"按 image id 缓存 Bitmap"是 Rust 侧资源管理的对照。
- OSC 矩阵：terminator 头部注释（TerminalEmulator.kt:27-180）是最全 checklist（0/1/2、4/10/11/12 Query、7、52 读写、133、1337、777/9）；逐项核对 libghostty-vt 覆盖，缺项按规范评估。OSC 52 读默认关 + 同步读开关（terminator MainViewModel.kt:809-841）与我们测试对接。
- 鼠标：ghostty（tracking mode 回读 + 无 mode 拒发 + 手势映射优先级）与 terminator（MouseGestureTracker 独立模块）+ anoterm（1000/1002/1003/1006 + DECCKM 建模）。DESIGN 要求参考 ghostty 实现。
- OSC 133 shell 状态机：puppy（AT_PROMPT/EXECUTING/TUI）、terminator（onShellIntegrationMark）、charon（CommandMark）三处独立实现；若 libghostty-vt 已暴露则优先用之。

## 15. 工程质量与反面教材

- 构建产物入库：puppy（106MB 的 build/.cxx）、rafacodephi（测试报告/产物）。我们 `.gitignore` 与 CI 纪律应保持。
- 远程下载即执行：Ply `curl | sh`（main.rs:100-104）与 proot rootfs 无校验下载；puppy/kosh 安装无版本校验。我们的 Bootstrap 坚持用户来源 + 原子改名，与"自动校验"诱惑保持距离（规范已定）。
- 吞错：`catch (_: Exception) {}`（ApexShell/Ply 通篇）、无意义 fallback——违反 DESIGN"尽早抛错"。
- 自研 VT 的必然不完备：Rin 545 行解析器仍是子集；puppy 无宽字符；ApexShell 正则染色。论证"终端状态以 Ghostty 为单一来源"的规范论点。
- fork 安全回退两例：AW 删文件回传门控 + JNI 释放错对象；AnsolePlus/kotlin-app/AW 齐删图像协议（省体积但丢能力）。fork 必须保留上游测试套件——kotlin-app 保留 22 个单测的做法是正例。

## 18. 结论

生态验证了本项目的三条主线判断：以 Ghostty 为 VT 唯一来源（自研必然不完备）、GPU 渲染（Canvas 系在 CJK 性能上无第二家达标）、会话与渲染归属 Rust（会话不随 Activity 走是跨生态共识）。可落地的参考点集中在搜索、设置下发、选择手势、PTY 收尾、IME 填坑、录制回放测试六处（§16 P0），均不触及规范禁区，建议按序纳入实现与验收对照。
